01从第一性原理出发

第一性原理

存储层级一直延伸到机器之外。从快到慢：SM 内的 L1/共享内存 → 单卡 HBM → 同节点多卡之间的 NVLink/NVSwitch → 跨节点的 InfiniBand/以太网。每往下一级，带宽都掉一个数量级左右。

为什么要用多卡？① 参数、梯度、优化器状态、激活值加起来放不进一张卡（内存）；② 想用更多 FLOPs 训练得更快（计算）。

怎么切？一次训练的计算可以看成沿四个维度展开：batch（数据）、宽度（隐藏维度 / 专家）、深度（层）、长度（序列）。选一个维度切开分给不同的卡，就得到一种并行方式：

  • 切 batch → 数据并行：每张卡有全部参数，处理不同数据，需要同步梯度；
  • 切宽度 → 张量并行（或专家并行）：每张卡有每层的一部分，需要交换激活值；
  • 切深度 → 流水线并行：每张卡有一部分层，需要在相邻卡之间传递激活值；
  • 切长度 → 序列并行。

单卡时用融合和分块减少内存访问；多卡时用复制和切分减少跨卡通信。能拿来交换的三样东西始终是：重新计算、存在本卡内存里、存在别的卡上再通信。

02集合通信操作

集合操作（collective operations）是分布式编程的概念原语，来自 1980 年代的并行计算文献。“集合”是指你描述的是一个涉及许多设备的通用通信模式，而不是自己管理点对点通信。这样通常更好也更快。

术语：rank 是一个设备（GPU）的编号，如 0、1、2、3；world size 是设备总数，如 4。

操作输入（rank 0 / 1 / 2 / 3）输出用途
Broadcastrank 0: [0,1,2,3]每个 rank: [0,1,2,3]rank 0 载入初始检查点后分发
Scatterrank 0: [0,1,2,3][0] / [1] / [2] / [3]理解 reduce-scatter 的铺垫
Gather[0] / [1] / [2] / [3]rank 0: [0,1,2,3]理解 all-gather 的铺垫
Reduce[0] / [1] / [2] / [3]rank 0: [6]理解 all-reduce 的铺垫
All-gather[0] / [1] / [2] / [3]每个 rank: [0,1,2,3]每个 rank 持有参数分片，前向前收集完整参数
Reduce-scatter[0,1,2,3] / [1,2,3,4] / [2,3,4,5] / [3,4,5,6][6] / [10] / [14] / [18]反向后对梯度求和，但分片存储
All-reduce同上每个 rank: [6,10,14,18]反向后对梯度求和，每个 rank 保留完整结果
All-to-all[0..3] / [4..7] / [8..11] / [12..15][0,4,8,12] / [1,5,9,13] / …MoE：把 token 路由到专家所在的卡
核心等式All-reduce = reduce-scatter + all-gather。把 all-reduce 拆成两半带来了灵活性：中间可以只保留自己那一片（这就是 ZeRO/FSDP 的基础）。

记忆方法：reduce 执行某种满足结合律和交换律的操作（sum、min、max）；scatter 是 gather 的逆；all 表示目的地是所有设备。均衡情况下，all-to-all 就像一次转置；它也能处理不均衡的切分，但切分越均衡越好。

补充：ring all-reduce 的通信量

N 张卡连成环，每张卡的数据大小为 S，切成 N 块。

Reduce-scatter 阶段：N−1 步，每步每张卡把一块（S/N）发给下一张卡，并把收到的块累加到自己的对应块上。结束时每张卡恰好拥有一块完整的和。

All-gather 阶段：再 N−1 步，把完整的块沿环传一圈。

每张卡总共发送 2(N−1)/N × S ≈ 2S。时间约为 2S / 带宽，与卡数 N 几乎无关。这就是 all-reduce 能扩展到很多卡的原因（代价是延迟随 N 增加，步数为 2(N−1)）。

03硬件：GPU 之间怎么连

家用配置

  • 同一台机器上的 GPU 通过 PCIe 总线通信（PCIe 7.0 x16 约 242 GB/s）。
  • 不同机器之间通过以太网通信（约 200 MB/s）。

数据中心配置

层级连接方式带宽（约）
单卡内HBM（B200）8 TB/s
节点内：通常 8 张 GPUNVLink 连到 NVSwitch（B200 的 NVLink 5.0）1.8 TB/s
节点间：一个 pod 约 256 个节点InfiniBand（PCIe → HCA 网卡 → IB 线缆）0.05 TB/s
pod 之间：数据中心以太网（经过 PCIe → CPU）更低

绕过 CPU：以太网要经过 CPU（把数据拷进内核 socket 缓冲区、组装 TCP 包、再拷到网卡的环形缓冲区）。RDMA（远程直接内存访问）让一张 GPU 直接读写另一张 GPU 的显存，不经过 CPU。InfiniBand 支持 RDMA，标准以太网不支持。

新进展：GB200/GB300 NVL72 每个托盘 8 张 GPU、每机架 9 个托盘，一个 NVLink 域内有 72 张 GPU。RoCE（基于融合以太网的 RDMA）让以太网也能绕过 CPU，比 InfiniBand 便宜但性能弱一些，Meta 在用。

NCCL

NVIDIA 集合通信库（NCCL）把集合操作翻译成在 GPU 之间发送的底层数据包：检测硬件拓扑（节点数、交换机、NVLink/PCIe），优化 GPU 之间的路径，启动 GPU kernel 来收发数据。

04torch.distributed 与实测带宽

PyTorch 的分布式库提供了集合操作的简洁接口（如 all_gather_into_tensor），支持多种后端：gloo（CPU）、nccl（GPU）。它也提供 FSDP 这样的高层算法，但本课不用。

def collective_operations_main(rank, world_size):   # 每个进程（rank）异步运行这个函数
    setup(rank, world_size)                         # init_process_group("nccl", ...)
    data = tensor([0., 1, 2, 3], device=f"cuda:{rank}") + rank
    dist.all_reduce(tensor=data, op=dist.ReduceOp.SUM)          # 原地修改
    # 每个 rank 都得到 [6, 10, 14, 18]

    input = torch.arange(world_size, dtype=torch.float32, device=...) + rank
    output = torch.empty(1, device=...)
    dist.reduce_scatter_tensor(output=output, input=input, op=dist.ReduceOp.SUM)
    # rank 0..3 分别得到 [6] [10] [14] [18]

    input, output = output, torch.empty(world_size, device=...)
    dist.all_gather_into_tensor(output_tensor=output, input_tensor=input)
    # 每个 rank 又得到 [6, 10, 14, 18]：all-reduce = reduce-scatter + all-gather

实测：通信有多快

讲义在 4 张 GPU 上对 1 亿个 fp32 元素（400 MB）做 all-reduce 和 reduce-scatter：

操作耗时发送字节的计算方式有效带宽
all-reduce1.4–1.6 mssize × 2 × (N−1)约 370–430 GB/s
reduce-scatter2.4–2.6 mssize × (N−1)（输入是 N 倍大的矩阵）约 450–490 GB/s

测量要点：先预热一次；计时前后都要 torch.cuda.synchronize() 和 dist.barrier()。all-reduce 的有效带宽约为 2 × 数据大小 / 总时长，与卡数和拓扑（环或树）无关；all-reduce 搬运的数据是 reduce-scatter 的 2 倍，耗时也约 2 倍，所以带宽相近。

05数据并行

下面三种策略都用深层 MLP 演示。MLP 是 Transformer 的计算瓶颈，所以很有代表性。

切分策略：每个 rank 拿到数据的一个切片，但持有全部参数和自己的优化器状态。

local_batch_size = batch_size // world_size
data = data[rank * local_batch_size : (rank + 1) * local_batch_size]
params = [get_init_params(num_dim, num_dim, rank) for _ in range(num_layers)]   # 相同种子 → 相同初值
optimizer = torch.optim.AdamW(params, lr=1e-3)

for step in range(num_steps):
    x = data
    for param in params:
        x = F.gelu(x @ param)
    loss = x.square().mean()
    loss.backward()
    for param in params:                        # 和普通训练唯一的区别：同步梯度
        dist.all_reduce(tensor=param.grad, op=dist.ReduceOp.AVG)
    optimizer.step()
  • 各 rank 的 loss 不同（在本地数据上计算）；
  • 梯度经过 all-reduce 后在各 rank 上相同；
  • 因此参数在各 rank 上保持一致。
补充：数据并行的代价

通信：每步 all-reduce 一次全部梯度，每卡约发送 2 × 参数字节数。和 batch 大小无关，所以 batch 越大、计算越多，通信占比越小。

内存：每张卡都存完整的参数、梯度和优化器状态，内存不随卡数减少。下一课的 ZeRO/FSDP 用 reduce-scatter + all-gather 解决这个问题。

06张量并行

切分策略：每个 rank 拿到每一层的一部分（按列切权重），所有数据和激活值都要在卡间传递。

local_num_dim = num_dim // world_size
params = [get_init_params(num_dim, local_num_dim, rank) for _ in range(num_layers)]  # 每个 rank 1/N 的列
x = data                                            # 所有 rank 都有完整输入
for layer in range(num_layers):
    x = F.gelu(x @ params[layer])                   # (batch, local_num_dim)：只算出一部分列
    activations = [torch.empty(batch_size, local_num_dim, device=...) for _ in range(world_size)]
    dist.all_gather(tensor_list=activations, tensor=x)   # 交换各自算出的列
    x = torch.cat(activations, dim=1)               # 拼回 (batch, num_dim)

每一层都要通信一次，而且通信在关键路径上（下一层必须等它）。所以张量并行需要非常快的互连，通常只在一个 NVLink 节点内使用。反向传播留作练习。

补充：通信量和 batch 成正比

每层 all-gather 的数据量是 batch × num_dim（激活值），随 batch 和序列长度增长；数据并行的通信量只和参数量有关。所以两者适合的场景不同：张量并行省的是每张卡的参数和计算，花的是大量激活通信。实际的 Megatron 式张量并行会把相邻两层分别按列、按行切，使每两个矩阵乘只需一次 all-reduce（下一课）。

07流水线并行

切分策略：每个 rank 拿到一部分层，激活值在相邻 rank 之间传递。

local_params = [get_init_params(num_dim, num_dim, rank) for _ in range(num_layers // world_size)]
micro_batches = data.chunk(num_micro_batches) if rank == 0 else [torch.empty(...) for _ in ...]
for x in micro_batches:
    if rank > 0:
        dist.recv(tensor=x, src=rank - 1)           # 从上一级收激活
    for param in local_params:
        x = F.gelu(x @ param)
    if rank + 1 < world_size:
        dist.send(tensor=x, dst=rank + 1)           # 发给下一级

问题是流水线气泡：第一张卡处理第一个 micro-batch 时，后面的卡都在等；最后一张卡处理完时，前面的卡已经空闲。把 batch 切成更多 micro-batch 可以缩小气泡。

气泡比例：总时间片 = m + p − 1，每张卡工作 m 个，空闲比例 = (p − 1) / (m + p − 1)。上图 p = 4、m = 4：3/7 ≈ 43% 的时间在空转。m = 32 时降到 3/35 ≈ 9%。

讲义的实现没有处理通信与计算的重叠，所以气泡并没有消除。流水线并行的好处是只在相邻卡之间点对点传递激活，通信量小，可以在较慢的互连上工作（跨节点）。

08还缺什么

  • 通信与计算的重叠；
  • 更通用的模型（有注意力等）；
  • 其他并行方式：序列并行、专家并行，以及它们的组合；
  • JAX/TPU 的做法：只需定义模型和切分策略，由 JAX 编译器处理其余一切（例如斯坦福的 Levanter）。这门课用 PyTorch，是为了让你看到如何从原语一步步搭起来。

09本课要点

并行方式切哪个维度通信什么对互连的要求
数据并行（DDP）batch梯度 all-reduce中等，可与反向重叠
FSDP / ZeRObatch + 参数存储all-gather + reduce-scatter中等
张量 / 专家并行宽度每层的激活非常快（NVLink）
流水线并行深度相邻阶段的激活可以较慢，但要处理气泡
序列并行长度注意力所需的 K/V 等视实现而定
  • 可以重新计算、存在内存里，或者存在别的卡上再通信。
  • 硬件在变快，但我们总想要更大的模型，所以这种层级结构会一直存在。

10自测题

Q14 个 rank 的输入分别为 [1,2,3,4]、[2,3,4,5]、[3,4,5,6]、[4,5,6,7]。reduce-scatter（求和）后各 rank 得到什么？再做 all-gather 呢？

按位置求和为 [10, 14, 18, 22]。reduce-scatter 后 rank 0 到 3 分别得到 [10]、[14]、[18]、[22]；再 all-gather，每个 rank 都得到 [10, 14, 18, 22]，与直接 all-reduce 的结果相同。注意输入长度必须是 world size 的倍数，才能均分。

Q27B 参数、bf16 梯度，用数据并行在 NVLink（约 900 GB/s 有效带宽）上 all-reduce 一次大约多久？

梯度 14 GB，每卡约发送 2 × 14 = 28 GB，约 28 / 900 ≈ 31 ms。如果一步训练的计算需要几百毫秒，并且能与反向重叠，通信开销就可以接受。

Q3为什么张量并行一般只在节点内用，而流水线并行可以跨节点？

张量并行每层都要同步激活，通信量随 batch × 序列长度增长，并且阻塞计算，节点间 InfiniBand 比 NVLink 慢数十倍，会严重拖慢。流水线并行只在阶段边界传一次激活，点对点、量小，慢互连也能承受。

Q48 级流水线，希望气泡比例低于 10%，至少需要多少个 micro-batch？

(p−1)/(m+p−1) < 0.1 → 7/(m+7) < 0.1 → m > 63，至少 64 个。

Q5数据并行里，为什么各 rank 的参数不需要额外同步也能保持一致？

初始参数相同（相同随机种子或广播），每步梯度经 all-reduce 后相同，优化器是确定性的，所以每步更新后的参数也相同。
