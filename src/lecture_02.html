01从第一性原理出发

第一性原理

深度学习里的一切（数据、参数、梯度、优化器状态、激活值）都是张量。对张量只有两件事要花钱：

  1. 存储：内存 = 元素个数 × 每个元素的字节数。
  2. 计算：每个操作做若干次浮点运算（FLOPs），同时要把输入从内存搬到计算单元、把输出搬回去（字节）。

硬件给出两个上限：峰值算力（FLOP/s）和内存带宽（bytes/s）。如果计算和搬运可以完美重叠，一个操作的耗时就是

time = max( FLOPs / 峰值算力 , bytes / 带宽 )

这一课剩下的所有内容，都是在把这两个公式应用到训练的各个环节上。

回忆课程的核心问题：给定固定资源（算力、内存），能训练出的最好模型是什么？前提是先搞清楚一次计算到底消耗多少资源。这一课的三类收获：

  • 机制：PyTorch 张量的语义，很直接。
  • 思维方式：养成做资源核算的习惯。
  • 直觉：对资源花在哪里有感觉。这一课没有“机器学习魔法”。

02两个餐巾纸估算

问题一：1024 张 H100 训练 70B 模型、15T token，要多久？

总计算量：6 × 70×10⁹ × 15×10¹² = 6.3×10²⁴ FLOPs（6ND 的来源见第 7 节）。

H100 的 bf16 稠密峰值约 989 TFLOP/s（规格表上的 1979 是带 2:4 稀疏的数字，要除以 2）。假设 MFU = 0.5：

每天能做 989.5×10¹² × 0.5 × 1024 × 86400 ≈ 4.38×10²² FLOPs。

所需天数：6.3×10²⁴ ÷ 4.38×10²² ≈ 144 天。

问题二：8 张 H100 用 AdamW，最大能训多大的模型？

每个参数要存：参数 bf16（2 字节）+ 梯度 bf16（2 字节）+ Adam 的一阶和二阶矩 fp32（4 + 4 字节）= 12 字节。

8 × 80 GB ÷ 12 字节 ≈ 533 亿参数（约 53B）。

这是上界：没算激活值（它取决于 batch size 和序列长度）。实际上很多实现还会保留一份 fp32 主权重，每参数 16 字节，上限会更低。

这些估算很粗糙，但能让你迅速判断一件事是否可行，这就是这一课想培养的习惯。

03内存核算：张量与浮点格式

张量

张量的 rank 是维度个数。Transformer 里常见 rank 4 的张量，例如 (B, S, H, D) = (batch, 序列长度, 头数, 每头维度)。一个张量占的内存由两件事决定：元素个数和数据类型。

x = torch.zeros(4, 8)          # 默认 float32
x.numel() * x.element_size()   # 32 × 4 = 128 字节

GPT-3 前馈层的一个矩阵 (4×12288, 12288)，fp32 下就占 2304 MiB，约 2.3 GB。

浮点格式：用位数换精度和范围

第一性原理

浮点数 = 符号 × 尾数 × 2^指数。指数位决定能表示的数量级范围（动态范围），尾数位决定相邻两个数之间有多密（精度）。总位数固定时，两者此消彼长。深度学习对精度很宽容，但对范围很敏感：梯度和激活值跨越很多数量级，一旦下溢成 0 或上溢成 inf，训练就崩了。

格式字节符号/指数/尾数特点
fp3241 / 8 / 23默认格式，范围和精度都够；科学计算里是基线
fp1621 / 5 / 10省一半内存，但范围小：1e-8 直接下溢成 0，训练易不稳定
bf1621 / 8 / 7Google Brain 2018 年提出；指数位和 fp32 一样，范围相同，只牺牲精度
fp8 E4M311 / 4 / 32022 年标准化，范围 [-448, 448]，H100 支持
fp8 E5M211 / 5 / 2范围 [-57344, 57344]，精度更低
NVFP40.51 / 2 / 12025 年 NVIDIA 提出；每个值只有 15 种取值，靠每块一个缩放因子扩大范围

NVFP4 的全部取值：±{0, 0.5, 1, 1.5, 2, 3, 4, 6}。每个小块共享一个缩放因子，所以整体范围反而更大，代价是同一块内的数不能随意差太多。Nemotron 3 Super 就是用 NVFP4 训练的。

混合精度训练

全用 fp32 能训练，但费内存；全用 fp16/bf16 有不稳定的风险。折中方案是混合精度（Micikevicius et al., 2017）：

  • 参数、激活值、梯度用 bf16；
  • 优化器状态用 fp32。

为什么优化器状态要 fp32？它是在许多步上累积的滑动平均（梯度的一阶、二阶矩）。每步的增量很小，低精度下“大数 + 小数”会把小数直接舍掉，累积误差会越来越大。PyTorch 的 AMP（torch.amp.autocast）会在安全的地方（如矩阵乘法）自动转成 bf16，在危险的地方（如 exp）保留 fp32。

张量在 GPU 上

张量默认在 CPU 内存里。要用 GPU 的大规模并行，就得把它搬到显存（x.to("cuda")），或者直接在 GPU 上创建。CPU 与 GPU 之间的传输很慢，应尽量避免来回搬。

04einops：给维度起名字

传统写法 x @ y.transpose(-2, -1) 很容易搞错维度：-2、-1 到底是哪一维？einops 受爱因斯坦求和约定启发，让你用名字描述维度。

einsum：带记账的广义矩阵乘法

z = einsum(x, y, "batch seq1 hidden, batch seq2 hidden -> batch seq1 seq2")
z = einsum(x, y, "... seq1 hidden, ... seq2 hidden -> ... seq1 seq2")  # ... 表示任意前导维度

规则只有一条：输出里没出现的维度会被求和。上例中 hidden 被求和掉，就是注意力分数 QKᵀ 的计算。

reduce 和 rearrange

y = reduce(x, "... hidden -> ...", "sum")                        # 等价于 x.sum(-1)
x = rearrange(x, "... (heads hidden1) -> ... heads hidden1", heads=2)  # 拆开一个合并的维度
x = einsum(x, w, "... hidden1, hidden1 hidden2 -> ... hidden2")
x = rearrange(x, "... heads hidden2 -> ... (heads hidden2)")       # 再合并回去

多头注意力里“把 d_model 拆成 heads × d_head”正是这种模式。

05计算核算：FLOPs 与 MFU

一次浮点运算（FLOP）是一次加法或乘法。两个极易混淆的缩写（读音还一样）：

  • FLOPs：浮点运算次数，衡量计算量。
  • FLOP/s（也写作 FLOPS）：每秒浮点运算次数，衡量硬件速度。

量级感

训练 GPT-3（2020）3.14×10²³ FLOPs
训练 GPT-4（2023，推测）2×10²⁵ FLOPs
H100 bf16 稠密峰值989 TFLOP/s
8 张 H100 跑 2 周（满峰值）9.6×10²¹ FLOPs

矩阵乘法的 FLOPs

y = x @ w，x 形状 (B, D)，w 形状 (D, K)。输出有 B×K 个元素，每个是长度 D 的点积：D 次乘法 + 约 D 次加法。

所以 FLOPs = 2 × B × D × K。

记法：矩阵乘法的 FLOPs = 2 × 三个维度之积。对每个 (i, j, k) 三元组，恰好一次乘法一次加法。

讲义在 H100 上实测 B=16384、D=32768、K=8192 的 fp32 矩阵乘法：8.8×10¹² FLOPs 用时 0.165 秒，实际 53 TFLOP/s。H100 的 fp32 峰值为 67.5 TFLOP/s，所以利用率约 0.79。注意峰值强烈依赖数据类型：同一张卡 bf16 峰值是 fp32 的约 15 倍。

MFU（Model FLOPs Utilization）

MFU = 实际 FLOP/s ÷ 峰值 FLOP/s只计模型本身需要的 FLOPs，不算通信、重计算等开销

MFU ≥ 0.5 就已经相当好了。为什么到不了 1？要回答这个问题，得看数据是怎么在 GPU 里流动的。

06算术强度与 roofline

计算一个东西分三步：把输入从内存送到计算单元 → 计算 → 把输出写回内存。耗时取决于算力（FLOP/s）和内存带宽（bytes/s）。H100 的两个数字：989 TFLOP/s（bf16）和 3.35 TB/s。

第一性原理

把耗时公式 max(FLOPs/峰值, bytes/带宽) 两边同除以 bytes，比较的就变成两个“每字节的 FLOPs”：

  • 加速器强度 = 峰值算力 ÷ 带宽 = 硬件每搬 1 字节能做多少运算。H100：989×10¹² ÷ 3.35×10¹² ≈ 295 FLOPs/字节。
  • 算术强度 = 操作的 FLOPs ÷ 搬运字节数 = 这个操作每搬 1 字节需要做多少运算。

算术强度 < 加速器强度 → memory-bound（算力在等数据）；反之 → compute-bound。

逐个算一遍（bf16，每个数 2 字节）

操作FLOPs搬运字节算术强度结论
ReLU（n 个元素）n 次比较读 2n + 写 2n0.25memory-bound
GeLU≈ 20n4n5memory-bound
点积（长度 n）2n − 14n + 2≈ 0.5memory-bound
矩阵 × 向量（n×n）n(2n − 1)2n² + 4n≈ 1memory-bound
矩阵 × 矩阵（n=1024）n²(2n − 1)6n²≈ n/3 = 341compute-bound

ReLU 的例子：搬运耗时 1.25 μs，计算耗时约 0.001 μs，差了三个数量级。几个推论：

  • 单独执行时，ReLU 并不比 GeLU 快。两者都卡在搬数据上，GeLU 多出来的计算是“免费”的。
  • 矩阵乘法的算术强度随 n 线性增长（n³ 次运算，只搬 n² 个数），所以只要矩阵足够大就是 compute-bound。临界点大约是 n ≈ 3 × 295 ≈ 890。
  • 训练是大矩阵乘矩阵，能跑满算力；推理的 decode 阶段本质是矩阵乘向量，所以是 memory-bound。
  • 加速器强度也和精度有关：换成 fp32，峰值算力降得比带宽快，临界点会移动。

Roofline 图

每种硬件对应一条折线，拐点就是它的加速器强度；每个操作对应横轴上一个位置。于是：

MFU ≤ min(1, 算术强度 ÷ 加速器强度)

07训练的核算：梯度与 6ND

反向传播回顾

简单线性模型 loss = 0.5 (x·w − 5)²，x = [1, 2, 3]，w = [1, 1, 1]。前向得到 x·w = 6，反向 ∂loss/∂w = (x·w − 5) x = [1, 2, 3]。PyTorch 的 loss.backward() 就是自动做这件事。

一层的反向要多少 FLOPs

考虑两层线性网络中的第二层 h2 = h1 @ w2，h1 形状 (B, D)，w2 形状 (D, D)。

前向：一次矩阵乘法，2BD² FLOPs。

反向：已知 h2.grad（形状 (B, D)），要算两样东西：

  • 对输入的梯度（继续往前传）：h1.grad = h2.grad @ w2ᵀ，2BD² FLOPs；
  • 对权重的梯度（用来更新）：w2.grad = h1ᵀ @ h2.grad，2BD² FLOPs。

反向合计 4BD²，是前向的 2 倍。

把所有层加起来，参数总量 N = Σ D²，数据点（token）数为 B：

前向 2BN + 反向 4BN = 6BN FLOPs / 每步整个训练：C ≈ 6 × 参数量 × 训练 token 数 = 6ND

这个推导针对 MLP，但对 Transformer 也是很好的近似，只要上下文不太长（注意力分数那部分 FLOPs 和参数无关，随序列长度平方增长，长上下文时不能忽略）。

补充：为什么是“每个参数每个 token 2 FLOPs”

前向时，每个权重对每个 token 恰好参与一次乘加（乘上输入、加到输出）。所以前向 FLOPs ≈ 2 × 参数量 × token 数，和网络形状无关。这也给推理一个快速估算：生成一个 token 大约要 2N FLOPs。

08优化器与内存全景

优化器家族

优化器在 SGD 基础上加了什么额外状态
Momentum梯度的指数滑动平均1 份
AdaGrad除以历史梯度平方和的平方根1 份
RMSPropAdaGrad，但梯度平方改成指数滑动平均1 份
AdamRMSProp + momentum2 份

讲义手写了 AdaGrad：

class AdaGrad(torch.optim.Optimizer):
    def step(self):
        for group in self.param_groups:
            for p in group["params"]:
                state = self.state[p]
                g2 = state.get("g2", torch.zeros_like(p.grad))
                g2 += torch.square(p.grad)          # 累积梯度平方
                state["g2"] = g2
                p.data -= group["lr"] * p.grad / torch.sqrt(g2 + 1e-5)

直觉：梯度一直很大的方向，步长被压小；梯度很小的方向，步长相对放大。每个参数都有了自适应的学习率。

一次训练要存什么

L 层、每层 D×D、batch 为 B 的网络：

内容精度字节数
参数bf162 × N
梯度bf162 × N
优化器状态fp32AdaGrad 4 × N，Adam 8 × N
激活值bf162 × B × D × L（与 batch 成正比）

讲义例子 B=2、D=4、L=3（N=48）：参数 96 + 梯度 96 + AdaGrad 状态 192 + 激活 48 = 432 字节；一步训练 6 × 2 × 48 = 576 FLOPs。Transformer 的核算更复杂，但思路完全一样，作业 1 会要求你亲手算一遍。

训练循环

for t in range(num_train_steps):
    x, y = get_batch()
    loss = F.mse_loss(model(x).mean(), y)   # 前向
    loss.backward()                         # 反向：算梯度
    optimizer.step()                        # 更新参数
    optimizer.zero_grad(set_to_none=True)   # 释放梯度内存

09用计算换内存

梯度累积

大 batch 能让训练更稳定，但激活值内存随 batch 线性增长，可能放不下。梯度累积的做法：

  1. 把一个 batch 切成若干 micro-batch，逐个做前向和反向；
  2. 梯度累加起来，不清零；
  3. 每处理完 batch_size / micro_batch_size 个 micro-batch，更新一次参数并清零梯度。

例：B=64、D=1024、L=16，bf16 激活值 2×64×1024×16 ≈ 2 MB；切成 4 份后，同时只需存约 0.5 MB。数学上结果完全相同（损失是样本平均），代价是失去了一部分并行度。

激活检查点（activation checkpointing）

也叫 gradient checkpointing 或 rematerialization。训练必须保存所有层的激活值，因为反向要用；推理不算梯度，只需保留当前层。

  • 前向：只在部分层保存激活值（检查点）。
  • 反向：需要时，从最近的检查点重新计算缺失的激活值。
# 全部保存：     x g1 h1 g2 h2 g3 h3 g4 h4
# 激活检查点：   x    h1    h2    h3    h4     （g 是层内中间结果，反向时重算）
x = torch.utils.checkpoint.checkpoint(layer, x)
策略激活内存额外计算
每层都存O(L)无
一层都不存O(1)O(L²)，每层都要从头重算
每 √L 层存一个O(√L)O(L)，约多做一次前向
补充：为什么是 √L

每隔 k 层存一个检查点，要存 L/k 个检查点；反向经过一段时，需要把这段 k 层的激活值重算并暂存。峰值内存 ≈ L/k + k，在 k = √L 时最小，为 2√L。重算总量是每层一次，也就是再做一次前向，训练整体大约慢 1/3（前向占 6N 里的 2N）。

讲义用小网络在 GPU 上实测峰值内存，开不开检查点都是约 202 MB。原因是这个玩具网络的参数和梯度远大于激活值；在真实的长序列、大 batch 训练中，激活值才是大头，检查点的效果才明显。

10本课要点

  • 一切都是张量上的操作：参数、梯度、激活值、优化器状态、数据。
  • 内存 = 元素数 × 字节数。bf16 保留 fp32 的范围、牺牲精度；混合精度训练里，优化器状态用 fp32。
  • einops 用命名维度来描述张量运算，更不容易出错。
  • 矩阵乘法 FLOPs = 2 × 三维乘积；训练每步 ≈ 6 × token 数 × 参数量。
  • 算术强度 vs 加速器强度决定 memory-bound 还是 compute-bound。矩阵乘法 compute-bound，逐元素操作 memory-bound。
  • 梯度累积和激活检查点都是用计算（或时间）换内存，以支持更大的 batch。

11自测题

Q1用 Adam 和混合精度（bf16 参数和梯度、fp32 的两个矩），7B 模型不算激活值要多少显存？

每参数 2 + 2 + 4 + 4 = 12 字节，7×10⁹ × 12 = 84 GB，单张 80 GB 的 H100 放不下。若再保留 fp32 主权重（+4 字节），是 112 GB。

Q2一个 (4096, 4096) 乘 (4096, 4096) 的 bf16 矩阵乘法，算术强度多少？在 H100 上是哪种 bound？

FLOPs ≈ 2×4096³ ≈ 1.37×10¹¹；字节 = 3 × 4096² × 2 ≈ 1.0×10⁸。算术强度 ≈ 4096/3 ≈ 1365 > 295，compute-bound。

Q3为什么说“单独执行时 ReLU 不比 GeLU 快”？

两者都要读 n 个数、写 n 个数，搬运量相同。算术强度分别是 0.25 和 5，都远低于 295，耗时都由搬运决定。GeLU 多出的计算藏在等数据的时间里。

Q4反向传播为什么是前向的 2 倍 FLOPs？

每个线性层反向要做两次同规模的矩阵乘法：一次算对输入的梯度（向前传递），一次算对权重的梯度（用于更新）。前向只有一次。

Q5batch=1 的 decode，为什么 MFU 很低？

每个线性层变成矩阵乘向量，算术强度约为 1，远低于 H100 的 295。GPU 大部分时间在等权重从 HBM 搬过来，理论 MFU 上限约 1/295 ≈ 0.3%。

Q6用 C = 6ND 反推：GPT-3 用了 3.14×10²³ FLOPs、175B 参数，训练了多少 token？

D = 3.14×10²³ ÷ (6 × 1.75×10¹¹) ≈ 3×10¹¹，约 300B token，和论文报告的一致。
