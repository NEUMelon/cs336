01从第一性原理出发

第一性原理

注意力的成本从哪来？softmax(QKᵀ)V 要算出 n×n 的分数矩阵，训练是 O(n²d)；推理时每个新 token 要读整个 KV cache，内存随 n 线性增长且永不压缩。本质上，注意力把全部历史原样保存，想查什么都能精确查到，代价是存储和计算随历史增长。

另一个极端是 RNN：把历史压缩进一个固定大小的状态，每步更新一次，成本与长度无关，但压缩会丢信息。这一课的前半部分，就是在“精确记忆”和“固定状态”之间找更好的折中。

稠密模型的成本从哪来？每个 token 都要经过每一个参数：FLOPs/token ≈ 2N。但并不是每个输入都需要全部知识。混合专家让每个 token 只激活一小部分参数：总参数量（容量）大，每 token 计算量（成本）小。

基础工具箱前面已经讲过：局部 + 全局注意力交替、系统工程优化。如果想要更激进、可能更大的收益呢？

02线性注意力

一个“很傻但很重要”的变换

设 Q, K ∈ ℝ^{n×d_k}，V ∈ ℝ^{n×d_v}，注意力为 ρ(QKᵀ)V。平方复杂度来自 QKᵀ。如果 ρ 是恒等函数（去掉 softmax），利用矩阵乘法的结合律：

(QKᵀ)V = Q(KᵀV)左边 n²d_k + n²d_v，右边 2n·d_k·d_v，对 n 是线性的

KᵀV 只是一个 d_k × d_v 的小矩阵。Shen et al. (2018)、Katharopoulos et al. (2020)（核函数版本）提出这种思路，它还和“快速权重编程器”（fast weight programmers）有联系。

循环形式：注意力其实是 RNN

加上因果掩码（位置 t 只看 ≤ t 的 token），把 KᵀV 按时间展开：

S_t = S_{t−1} + k_t v_tᵀ ， y_t = q_tᵀ S_tS_t 是 d_k × d_v 的状态矩阵

这就是一个 RNN：状态大小固定，每步 O(d_k d_v)，推理时不需要 KV cache。这种对偶性让我们两头占便宜：

  • 训练用并行（平方）形式，所有位置一起算，能用矩阵乘法跑满 GPU；
  • 推理用串行（线性）形式，每步常数成本、常数内存。

若对 S_{t−1} 乘一个固定衰减系数 γ，就得到 RetNet。

补充：状态 S 在存什么

S = Σ k_i v_iᵀ 是一个联想记忆：用 key 查询 value。qᵀS = Σ (q·k_i) v_iᵀ，就是用未归一化的相似度对 value 加权求和。问题在于它只加不减，d_k × d_v 的容量有限，存多了就互相干扰。下面的改进都在解决“怎么忘、怎么改写”。

MiniMax M1（以及 MiniMax-Text-01）采用 7:1 混合：每 7 层线性注意力配 1 层全注意力。效果总体不错，并且在上下文长度上展现出线性扩展。

Mamba-2：加入数据相关的门控

S_t = γ_t S_{t−1} + k_t v_tᵀ ， y_t = q_tᵀ S_t + v_tᵀ D ， γ_t = f(x_t)

和线性注意力的区别是衰减系数 γ_t 由当前输入决定：模型可以选择性地遗忘。Mamba-2 论文有大量理论论证，但机制上就是“用门控让线性注意力更有表达力”（又一次：门控是好东西）。它仍有对偶性：γ 可以并行算出，再套用并行形式。

NVIDIA Nemotron 3 使用 Mamba 与注意力的混合（大约 3:1），效果和同类模型相当甚至更好。

Gated DeltaNet：选择性擦除

S_t = γ_t (I − β_t k_t k_tᵀ) S_{t−1} + β_t k_t v_tᵀ ， y_t = q_tᵀ S_t

两处新东西：β_t 是“写入强度”门（β = 0 表示这一步什么都不写）；(I − β k kᵀ) 先擦掉状态里当前 key 方向上的旧内容，再写入新 value。

从第一性原理推导 delta rule。把状态 S 看作一个线性映射，希望它能把 key 映射到对应的 value：Sᵀk_t ≈ v_t。对这个目标的平方误差做一步在线梯度下降：

L(S) = ½‖Sᵀk_t − v_t‖²， ∇_S L = k_t (k_tᵀS − v_tᵀ)

S ← S − β_t k_t (k_tᵀS − v_tᵀ) = (I − β_t k_t k_tᵀ) S + β_t k_t v_tᵀ

正好是 DeltaNet 的更新（γ_t 再额外加一个整体衰减）。所以 Gated DeltaNet 的每一步是在推理时对“记忆”做一次梯度下降，这就是它和测试时训练（test-time training）的联系。朴素线性注意力只会累加，delta rule 则会纠错。

Qwen 3.5 / Qwen3-Next 采用 3:1 的 Gated DeltaNet / 注意力混合，效果合理，推理特性好。

混合模型的效果

严格控制变量的消融实验不多，但有证据表明：只保留少量全注意力层（较低的混合比例）时 loss 仍然很低。直觉是，线性层负责大部分局部加工，少数全注意力层负责精确检索远处的信息。

03另一条路：稀疏注意力（DSA）

混合模型之外的另一种选择是保留注意力，但不再关注所有 token。DeepSeek Sparse Attention（DeepSeek V3.2、GLM-5 使用）：

  1. 一个非常轻量的索引器（indexer）为每个 query 给所有历史 token 打分；
  2. 只选出得分最高的 top-k 个 token，做真正的注意力。

索引器仍是 O(n²)，但它极其便宜（头少、维度低、可以用低精度），而昂贵的主注意力降到 O(nk)。重要的是，DSA 可以在稠密短上下文预训练之后事后适配，不需要从头训练。

04混合专家：是什么，为什么流行

MoE 把一个大的前馈网络替换成很多个前馈网络（专家）和一个选择器（路由器）。每个 token 只被送到少数几个专家。增加专家数量不会增加每 token 的 FLOPs。据传 GPT-4 就是 MoE。

为什么 MoE 越来越流行

  • 同样的 FLOPs，参数越多效果越好（Fedus et al., 2022：专家数越多，loss 越低）。
  • 训练更快：达到同样 loss 所需的计算更少（OLMoE）。
  • 和稠密模型相比很有竞争力：目前最强的开放模型大多是 MoE，推理也快。
  • 容易并行到多设备：每个专家可以放在不同的 GPU 上（专家并行）。

Qwen、DeepSeek 等中国团队很早就在小规模上做了大量 MoE 工作和消融实验，结果普遍正面。

为什么 MoE 以前没那么流行

  • 基础设施复杂，优势主要体现在多节点场景；
  • 训练目标有些启发式，有时不稳定。

通常是把 MLP 换成 MoE 层；把注意力头做成专家的（ModuleFormer、JetMoE）较少见。变化点主要在三处：路由函数、专家大小、训练目标。

05路由

大多数路由算法归结为“选 top-k”。三种思路：token 选专家、专家选 token、通过全局优化分配。几乎所有 MoE 都用token 选专家的 top-k。

方法说明
Top-k绝大多数 MoE。Switch Transformer k=1；GShard、Grok、Mixtral k=2；Qwen、DBRX k=4；DeepSeek k=7 左右
哈希按 token 哈希固定分配，常用作基线
强化学习最早的工作（Bengio 2013）用过，现在不常见
线性分配把路由当成匹配问题求解（Clark 2022）

Top-k 路由的细节

对 token 的隐状态 u_t，每个专家 i 有一个向量 e_i：

s_{i,t} = softmax_i(u_tᵀ e_i)， g_{i,t} = s_{i,t} 若 s_{i,t} ∈ TopK，否则 0

h_t = u_t + Σ_i g_{i,t} · FFN_i(u_t)

门控其实就是一个逻辑回归打分器。DeepSeek V1/V2、Grok、Qwen 在 top-k 之前做 softmax；Mixtral、DBRX、DeepSeek V3 在 top-k 之后对选中的专家重新 softmax（V3 用 sigmoid 打分）。

细粒度专家与共享专家

DeepSeek、Qwen 等的改进（最早来自 DeepSpeed-MoE）：

  • 细粒度专家：把每个专家切小（例如 1/4 大小），数量翻 4 倍，激活数也翻 4 倍。总计算不变，但组合方式多得多，专家可以更专精。
  • 共享专家：少数专家对所有 token 始终激活，负责通用知识，让路由专家专注于差异化的部分。

DeepSeek 的消融显示更多专家、共享专家都有帮助；OLMoE 的消融显示细粒度专家有收益，共享专家没有。

06怎么训练 MoE

核心矛盾：训练时要稀疏才能高效，但离散的门控决策不可微。三种办法：

  1. 强化学习优化门控策略：REINFORCE 能用（Clark et al., 2020），但没有明显更好，梯度方差大、复杂，所以很少用。它是“正确”的解法，但不实用。
  2. 随机扰动：Shazeer et al. (2017) 在路由打分上加高斯噪声，专家会更鲁棒，softmax 让模型学会给 k 个专家排序。Fedus et al. (2022) 用乘性均匀抖动，后来 Zoph et al. (2022) 又去掉了。
  3. 启发式均衡损失：实际上大家都用这个。

负载均衡损失

系统效率要求专家被均匀使用：一个专家过载，整批都要等它；一个专家没人用，就是浪费参数。Switch Transformer 的辅助损失：

loss_aux = α · N · Σᵢ fᵢ · Pᵢfᵢ = 分到专家 i 的 token 比例；Pᵢ = 路由器给专家 i 的平均概率；N = 专家数

fᵢ 来自 argmax，不可微；Pᵢ = (1/T) Σₓ pᵢ(x) 可微。对某个 token 的 pᵢ(x) 求导：

∂loss/∂pᵢ(x) = (αN/T) · fᵢ = (αN/T²) Σₓ 1[argmax p(x) = i]

专家 i 被用得越多（fᵢ 越大），就越强烈地压低路由器给它的概率。当所有 fᵢ = Pᵢ = 1/N 时，损失取得最小值 α。

DeepSeek V1/V2 同时用了专家级均衡（同上）和设备级均衡（按设备聚合 f 和 P），V2 还加了通信均衡损失（进出都要平衡）。

DeepSeek V3：“无辅助损失”的均衡

给每个专家一个偏置 bᵢ，只在选 top-k 时加到打分上（不影响门控权重）。每步之后在线调整：专家过载就减小 bᵢ，负载不足就增大 bᵢ。这样不需要往损失里加一项去干扰主目标。不过 V3 其实还保留了一个很小的序列级辅助损失，所以并不完全“无辅助损失”。去掉均衡损失会怎样？专家使用会严重失衡，少数专家吃掉大部分 token。

07MoE 的系统问题与训练难题

并行与通信

MoE 很适合并行：每个专家的 FFN 可以放进一个设备，这就带来了专家并行。代价是路由之后的 all-to-all 通信，以及每个专家收到的 token 数不固定。MegaBlocks 等库用块稀疏矩阵乘法处理不均匀的负载，很多开放 MoE 都用它。Nemotron 3 的新想法：先把激活值降维再发送，以减少通信量。

MoE 的额外随机性

为什么 MoE 推理会有额外的随机性？每个专家有容量上限，超出的 token 会被丢弃（token dropping）。而容量是按整个 batch 计算的，所以别人的请求可能挤掉你的 token，同一个输入在不同 batch 里结果不同。

稳定性

路由器的 softmax 很容易出数值问题。解决办法：路由器单独用 fp32 计算，有时再对路由 logits 加 z-loss（Zoph et al., 2022）。去掉 z-loss 会出现 loss 尖峰。

微调

稀疏 MoE 在小的微调数据上容易过拟合。Zoph 的办法是只微调非 MoE 的 MLP；DeepSeek 的办法是用大量数据（140 万条 SFT）。

Upcycling：用稠密模型初始化 MoE

把预训练好的稠密模型的 MLP 复制 N 份作为专家初始值，再继续训练。

  • MiniCPM：8 个专家、top-2、约 4B 激活参数，用约 520B token 训练后比原模型有提升。
  • Qwen MoE：从 Qwen 1.8B 初始化，60 个专家 + 4 个共享专家、top-4，结构类似 DeepSeekMoE，是最早确认成功的 upcycling 之一。

MLA：多头潜在注意力

基本想法：把 Q、K、V 都表示成一个低维潜在向量的函数。

c_t^{KV} = h_t W^{DKV}（压缩到 d_c 维），然后 K = c_t^{KV} W^{UK}，V = c_t^{KV} W^{UV}。

好处：KV cache 只需存 c_t^{KV}。更妙的是，计算注意力分数时

⟨h W^Q, c W^{UK}⟩ = ⟨h W^Q (W^{UK})ᵀ, c⟩

W^{UK} 可以合并进 Q 的投影，推理时根本不用把 K 还原出来。（训练时它们也压缩 Q，用于省激活内存。）

麻烦：RoPE 会破坏这种合并。加了旋转后变成 h W^Q R_q R_kᵀ W^{UK} c，R 依赖位置，夹在两个矩阵中间，无法预先合并。

解法：额外保留少量不压缩的“解耦” key 维度专门承载 RoPE。

补充：MLA 省了多少

DeepSeek V2/V3 中 d_c = 512，解耦 RoPE key 为 64 维，每 token 每层只缓存 576 个数。同样 128 个头、头维度 128 的标准多头注意力要缓存 2 × 128 × 128 = 32768 个数，MLA 小了约 57 倍，而论文报告效果不降反升。

MTP：多 token 预测

在主模型之后接一个小型轻量模块，额外预测更远的 token（思路类似 EAGLE 的投机解码草稿头）。它提供更密的训练信号，推理时也可以用来做投机解码。DeepSeek V3 实际只多预测了 1 个 token。

09本课要点

  • 去掉 softmax 后，线性注意力利用结合律把 O(n²) 变成 O(n)，并且等价于一个状态固定的 RNN：训练用并行形式，推理用循环形式。
  • Mamba-2 加数据相关的遗忘门；Gated DeltaNet 进一步做“选择性擦除”，本质是对记忆做在线梯度下降。
  • 当前主流做法是混合：3:1 到 7:1 的线性层配少量全注意力层；或者用 DSA 这类稀疏注意力。
  • MoE 利用稀疏性：并非每个输入都需要整个模型。增加专家不增加每 token 的 FLOPs。
  • 离散路由难以优化，但 top-k 加负载均衡这种启发式方法效果很好。
  • 大量实证表明 MoE 有效且划算：细粒度专家、共享专家、无辅助损失均衡、MLA 是 DeepSeek 系列的关键设计。

10自测题

Q1n = 32768、d_k = d_v = 128 时，普通注意力和线性注意力的计算量相差多少倍？

普通：n²(d_k + d_v) = 32768² × 256 ≈ 2.7×10¹¹；线性：2n·d_k·d_v = 2 × 32768 × 128² ≈ 1.1×10⁹。约 256 倍，恰好是 n / d。

Q2推导：delta rule 是哪个目标函数的一步梯度下降？

目标是 ½‖Sᵀk_t − v_t‖²，让记忆 S 把当前 key 映射到当前 value。梯度 k_t(k_tᵀS − v_tᵀ)，步长 β_t，得到 (I − β_t k_t k_tᵀ)S + β_t k_t v_tᵀ。

Q3DeepSeek V3 每个 token 前向大约多少 FLOPs？和同样总参数量的稠密模型相比呢？

约 2 × 37B ≈ 74 GFLOPs/token（忽略注意力分数部分）。671B 稠密模型约 1342 GFLOPs/token，是 MoE 的 18 倍。但 MoE 的全部 671B 参数仍要占显存。

Q4为什么需要负载均衡？不做会怎样？

路由容易“富者更富”：被选中多的专家训练得更好，于是更常被选中，最后少数专家处理大部分 token。结果是参数浪费（其他专家没学到东西），并且系统上过载的专家成为瓶颈，超出容量的 token 被丢弃。

Q5为什么 RoPE 和 MLA 的“吸收”技巧冲突？DeepSeek 怎么解决？

吸收技巧依赖 W^Q (W^{UK})ᵀ 可以预先相乘；加入 RoPE 后，中间多了依赖位置的旋转矩阵，不能与位置无关的权重预先合并。DeepSeek 让大部分维度不加 RoPE（可吸收），另加少量单独的维度承载 RoPE，并把这部分 key 直接缓存。

Q6为什么同一个 prompt 在 MoE 服务上可能每次输出不同（即使温度为 0）？

专家容量是按整个 batch 计算的。和你一起被批处理的其他请求会影响每个专家的负载，从而决定你的某些 token 是否被丢弃或改路由，所以结果依赖于 batch 里的其他请求。
