01从第一性原理出发

第一性原理

过滤的本质是一个分布匹配问题：我们手上有一小份“好数据长什么样”的目标数据 T，和一大堆原始数据 R，想从 R 中找出和 T 相似的子集。要求是：能从 T 泛化（找到的不应该只是 T 的复制品）；要极快（R 非常大）。

去重的本质是比较每一对数据，朴素做法是 O(n²)，在万亿 token 规模上不可行。关键工具是哈希：把“比较两两是否相似”变成“看它们是否落进同一个桶”，时间变成线性。对近似重复，需要一种特殊的哈希，让相似的东西更容易碰撞。

配比的本质是在“高质量”和“多样性、数据量”之间权衡。每个数据源都是有限的：给小的高质量源太大权重，就要重复很多个 epoch，最终过拟合。而这个权衡依赖训练规模。

02转换：把原始数据变成文本

原始数据不是文本，而是 HTML、PDF（arXiv）或目录（代码仓库）。

HTML 转文本

  • 去掉模板内容（导航栏、广告等），提取正文；
  • 图片、表格怎么办？
  • 这个过程天生有损（要把二维页面线性化）；
  • 工具（基于规则）：trafilatura、resiliparse、jusText、lynx 等；
  • 转换的准确性会影响模型效果（DCLM：直接用 WET 文本比从 WARC 重新提取差）。

FinePDFs

来源仍是 Common Crawl。PDF 很大，常被截断，需要重新爬取；用视觉语言模型（RolmOCR）或 Docling 做 OCR，并想办法让它们跑得快；再做大量清洗和过滤。很多版面信息会丢失。

03过滤

通用框架

  1. 基于 R 和 T 估计一个模型，得到一个打分函数；
  2. 根据分数决定保留 R 中的哪些样本。
分类器类型打分例子
T 的生成模型score(x) = p_T(x)KenLM n-gram 模型（CCNet）
简单判别分类器score(x) = p(T | x)fastText（DCLM、语言识别）

使用方式：保留 score(x) ≥ 阈值 的样本（可以随机化）。

补充：为什么用这么简单的模型

分类器要在几十万亿 token 上运行一遍，成本必须远低于训练本身。fastText 是词袋 + n-gram 特征上的线性分类器，在 CPU 上每秒能处理大量文档；KenLM 是 n-gram 语言模型，也极快。用大模型直接打分太贵，常见做法是先用 LLM 给少量样本打标签，再蒸馏成一个 fastText 分类器（如 Nemotron-CC、phi-1）。

是否使用基于模型的过滤？有些数据集刻意不用（C4、Gopher、RefinedWeb、FineWeb、Dolma），担心引入偏见；有些用了（GPT-3、LLaMA、DCLM），这正在成为常态。调研论文：A Survey on Data Selection for Language Models。

应用一：语言识别

目标：找出某种语言（如英语）的文本。fastText 语言识别是现成的分类器，支持 176 种语言，在多语言网站（维基百科、翻译网站 Tatoeba、东南欧新闻 SETimes）上训练。Dolma 保留 p(英语) ≥ 0.5 的页面。

OpenWebMath：从 Common Crawl 收集大规模数学文本。先用规则过滤（例如包含 LaTeX 命令）；用在 ProofPile 上训练的 KenLM，保留困惑度 < 15000 的；再训练 fastText 分类器预测是否为数学写作（有数学时阈值 0.17，否则 0.8）。结果得到 14.7B token，在上面训练的 1.4B 模型胜过用 20 倍数据训练的模型。

应用二：质量过滤

GPT-3：正例取自 {维基百科、WebText2、Books1、Books2}，负例取自 Common Crawl。基于词特征训练线性分类器，然后按分数随机保留：

def keep_document(score: float) -> bool:
    return np.random.pareto(9) > 1 - score   # 分数越高越可能保留，低分文档也有小概率被保留

随机保留的好处：不会把某一类“不像参考文本”的内容完全删光，保留了一些多样性。

LLaMA / RedPajama：正例取自被维基百科引用的页面，负例取自 Common Crawl，保留被分类为正例的文档。

phi-1：理念是用非常高质量的数据（“教科书”）训练一个小模型（1.5B）。包括 GPT-3.5（后来是 GPT-4）生成的合成数据和过滤后的数据。

R = The Stack 的 Python 子集。用 GPT-4 和提示“判断它对一个想学习基础编程概念的学生的教育价值”，给 R 的 10 万个样本打标签，得到 T。在 T 上训练随机森林分类器（特征是预训练代码模型的输出嵌入），用它从 R 中选出正例。

HumanEval 结果：在 The Stack Python 子集上训练 1.3B 模型，96K 步后 12.19%；在过滤后的子集上训练，36K 步后 17.68%。步数更少，效果更好。

应用三：毒性过滤

Dolma 使用 Jigsaw Toxic Comments 数据集（2018）。这个项目的目标是帮助人们在网上更好地讨论；数据是维基百科讨论页的评论，标注为 {toxic、severe_toxic、obscene、threat、insult、identity_hate}。

过滤的效果依赖规模

不存在唯一最优的过滤阈值：

  • 训练得更久，就需要更多（质量较低的）数据；
  • 训练得更短，就需要更少（质量更高的）数据。

原因和上一课的数据重复一样：严格过滤后的数据量小，训练 token 多时就要重复很多遍，重复带来的损失会超过质量带来的收益。

小结：过滤对构建好模型至关重要。配方：定义目标数据（好数据长什么样），然后外推到原始数据。

04去重

两类重复：

  • 完全重复：镜像站点、GitHub fork 等。
  • 近似重复：只相差几个 token 的文本，如服务条款和许可证（MIT license）、套用模板的公式化写作、复制粘贴时的细微格式差异。

例：一段商品描述在 C4 中重复了 61,036 次。

去重能让语言模型更好（Lee et al., 2021）：训练更高效（token 更少）；避免记忆（可缓解版权和隐私问题）。

设计空间：

  1. 什么是一个条目：句子、段落，还是文档？
  2. 怎么匹配：完全相同、存在共同的子条目，还是共同子条目的比例？
  3. 采取什么动作：全部删除，还是只保留一个？

核心挑战：去重本质上是条目之间的比较，需要线性时间的算法才能扩展。

哈希函数

哈希函数 h 把条目映射成哈希值（整数或字符串），哈希值远小于条目本身。碰撞：x ≠ y 但 h(x) = h(y)。效率和抗碰撞性之间有权衡：密码学哈希（SHA-256）抗碰撞但慢（比特币用它）；DJB2、MurmurHash、CityHash 不抗碰撞但快（哈希表用它们）。这里用 MurmurHash（mmh3.hash("hello")）。

精确去重

items = ["Hello!", "hello", "hello there", "hello", "hi", "bye"]
hash_items = itertools.groupby(sorted(items, key=mmh3.hash), key=mmh3.hash)   # 按哈希值分组
deduped_items = [next(group) for h, group in hash_items]                  # 每组保留一个

优点：简单、语义清晰、精度高；这种写法是 MapReduce 式的，容易并行扩展。缺点：去不掉近似重复。

C4 的做法：条目是 3 句话的片段，精确匹配，只保留一个。警告：从文档中间删掉一个 3 句片段后，剩下的文档可能不连贯。

Jaccard 相似度与 MinHash

先定义相似度：Jaccard(A, B) = |A ∩ B| / |A ∪ B|。例如 A = {1, 2, 3, 4}，B = {1, 2, 3, 5}，交集 3、并集 5，Jaccard = 0.6。两个文档（通常表示成 n-gram 的集合）Jaccard 相似度 ≥ 阈值时，就认为是近似重复。算法挑战：在线性时间内找出近似重复。

MinHash：一个随机哈希函数 h，使得 Pr[h(A) = h(B)] = Jaccard(A, B)。通常我们希望不同条目哈希到不同的值，但这里我们希望碰撞概率取决于相似度。

def minhash(S: set[str], seed: int):
    return min(mmh3.hash(x, seed) for x in S)

为什么成立？把 A 和 B 写成特征矩阵：

元素 | A | B
1    | 1 | 1
2    | 1 | 1
3    | 1 | 1
4    | 1 | 0
5    | 0 | 1

随机哈希函数相当于对 A ∪ B 中的元素做一个随机排列，min 就是排在最前面的那个。每个元素排第一的概率相同。如果排第一的是 1、2、3（交集中的元素），A 和 B 的 min 相同；如果是 4 或 5，则不同。所以碰撞概率 = |A ∩ B| / |A ∪ B| = 3/5。用 100 个不同种子估计，结果与 0.6 相差不到 0.01。

现在可以对条目做哈希了，但一次碰撞并不能告诉我们 Jaccard(A, B) 是否超过阈值。

局部敏感哈希（LSH）

只用一个 MinHash 函数时，A 和 B 碰撞的概率就等于 Jaccard(A, B)：平均来说越相似越容易碰撞，但随机性很大。目标：让 Jaccard 超过阈值的对几乎总是碰撞，低于阈值的几乎从不碰撞。需要把概率“锐化”。

解决办法：用 n 个哈希函数，分成 b 个带（band），每带 r 个（n = b·r）：

h1 h2 h3 h4  |  h5 h6 h7 h8  |  h9 h10 h11 h12      (n = 12, b = 3, r = 4)

规则：只要某一个带中的所有哈希值都相同，A 和 B 就碰撞。这种“与—或”结构锐化了阈值。

设 s = Jaccard(A, B)：

P[某个固定的带完全匹配] = s^r（带内“与”）

P[A, B 碰撞] = 1 − (1 − s^r)^b（带间“或”）

例：s = 0.8，b = 5，r = 10 → s^r ≈ 0.107，碰撞概率 ≈ 0.43。

阈值（相变发生的位置）约为 (1/b)^{1/r}。在这个点上，一个带匹配的概率是 1/b，碰撞概率约为 1 − (1 − 1/b)^b ≈ 1 − 1/e ≈ 0.63。

  • 增大 r：阈值更陡，曲线右移（更难匹配）。
  • 增大 b：曲线左移（更容易匹配）。

Lee et al. (2021) 的设置：n = 9000，b = 20，r = 450，阈值 (1/20)^{1/450} ≈ 0.993，只把极其相似的文档视为重复。

补充：为什么这是线性时间

每个文档只算一次 n 个 MinHash，然后对每个带把 r 个值拼起来再哈希，放进 b 个哈希表之一。只有落进同一个桶的文档对才需要进一步比较。总成本约为 O(文档数 × n)，而不是 O(文档数²)。

05数据配比

语言模型用多个数据源训练（例如 Marin 的 token 统计、The Pile 的 22 个领域）。关键问题：各数据源应该用什么分布？例如 {维基百科: 0.3, CC: 0.5, GitHub: 0.2}。

基线方法：

  • 凭感觉：根据直觉手动设 p(s)（相当常见）；
  • 均匀采样：p(s) ∝ 1；
  • 按比例混合：p(s) ∝ 数据源的 token 数。

直觉：应该给质量更高的数据源更大的权重。但是：① 要保证多样性（文学、代码、论文这些不可比的来源都要有）；② 每个数据源都是有限的，权重太大就要重复多个 epoch。

例：低质量源有 10T token（充足），高质量源只有 10B token（稀缺）。朴素配比各 0.5，训练 1T token：

低质量源 epoch 数 = 0.5 × 1T / 10T = 0.05；高质量源 epoch 数 = 0.5 × 1T / 10B = 50。

在高质量数据上重复 50 遍，很可能过拟合。

UniMax

场景：为多语言模型平衡不同语言。以前的做法介于均匀和按比例之间：p(s) ∝ num_tokens(s)^α，α ∈ [0, 1]（温度采样）。UniMax 的想法：均匀采样各数据源，但给每个数据源的 epoch 数设一个硬上限 C：对所有 s，p(s) × 训练总 token 数 ≤ C × num_tokens(s)。

基于回归的配比（RegMix、OLMix）

  1. 定义配比的分布（例如 Dirichlet），从中采样许多配比；
  2. 对每个配比训练小模型，测得目标指标（基于下游评测，小心别过拟合）；
  3. 拟合回归模型（线性回归、梯度提升树等）：配比 → 指标；
  4. 在回归模型上找最优配比。

这和 scaling laws 如出一辙，要在小规模和大规模之间权衡成本和准确性。两个“祈祷”：希望 1，回归模型在最小值附近是准确的；希望 2，小规模的最优配比能迁移到大规模。

模拟 epoch

至少有一个效应依赖规模：同样是 10T 低质量 + 10B 高质量，小模型训练的 token 少，在高质量数据上不会重复，所以最优配比会是 {低: 0.1, 高: 0.9}。但用这个配比训练大模型，会在高质量数据上重复大量 epoch 而过拟合。

解决办法：让小规模看起来像大规模（这是本课程反复出现的主题）。把所有数据源按比例下采样：小规模训练 10B、大规模训练 1T，比例是 0.01，于是下采样后的数据源为 {低: 100B, 高: 100M}。在这个下采样的数据上，重复太多的配比表现不会好，所以找到的最优配比会更均衡，比如 {低: 0.7, 高: 0.3}。

小结：问题是怎样给不同数据源（维基百科、通用网页、代码）加权；基于回归的配比在小规模上估计“配比 → loss”并优化（类似 scaling laws）；重要的考量是 epoch 和过拟合（解法：设上限，或模拟 epoch）。

06后训练数据

配方：① 定义一组环境；② 定义一组任务或 prompt；③ 从一个强模型（教师）收集回答。

OpenThoughts

用 QwQ-32B 作为教师，生成 120 万个样本。问题来自 27 个人类或合成来源（StackExchange、NuminaMath、化学等）。发现：

  • 每个 prompt 采样多个（16 个）回答是有帮助的；
  • 更好的模型不一定是更好的教师：QwQ-32B 比 DeepSeek-R1 更适合当教师；
  • 按答案正确性过滤没有帮助；
  • 较小的高质量来源（如 OpenMath-2-Math）比大而杂的来源更好。

软件工程数据

  • SWE-smith：给定一个仓库，用 LM 生成任务（让 LM 往代码里引入 bug）。128 个 GitHub 仓库产生了 5 万个任务。
  • SWE-rebench：从 3400 个 GitHub 仓库的 45 万个 PR 中得到 2.1 万个交互式 Python 软件工程任务；用 Qwen 2.5-72B-Instruct 安装依赖、评估 PR 质量。
  • SWE-Zero：软件工程任务的依赖很重（不像数学题或编程竞赛），搭建成千上万个 Docker 镜像是基础设施噩梦。观察：强模型不需要执行反馈也能解决很多任务，因为它们内部有代码语义的“世界模型”。于是生成 30 万条不需要特定仓库执行环境的智能体轨迹（来自 15 万个 GitHub PR），使用 OpenHands 框架，并删除未来的 git 提交以防智能体“git 作弊”（直接查看答案）；从 Qwen3-Coder-480B 蒸馏并过滤。另有 SWE-Hero：1.3 万条需要执行反馈的轨迹。
  • SWE-ZERO-12M：把 SWE-Zero 扩展到 1200 万条轨迹，用 SWE-rebench-v2 的任务（3.2 万可执行 + 12 万不可执行），由一个很小的模型（mini-coder-1.7b，pass@100 为 50.4）配合 mini-swe-agent 框架生成。

小结：生成 prompt 的方式有全合成、半合成（真实环境 + 合成任务）、真实（GitHub PR）；回答来自能力强且适合当教师的模型；代码环境很痛苦；有大量过滤和其他细节。

07本课要点

  • 过滤：为“好数据长什么样”训练分类器（语言识别、质量、毒性），并在原始数据上外推。
  • 去重：哈希让模糊匹配能扩展到大规模数据；MinHash 使碰撞概率等于 Jaccard 相似度，LSH 用分带锐化阈值。
  • 配比：在小规模上尝试不同配比，外推出最优配比；注意 epoch 与过拟合（设上限或模拟 epoch）。
  • 后训练数据看起来很像评测任务，大量使用合成数据。
  • 大量数据工作是领域相关的，需要反复查看样本。

08自测题

Q1A = {a, b, c, d, e}，B = {c, d, e, f}，Jaccard 相似度是多少？一个 MinHash 碰撞的概率呢？

交集 {c, d, e} 大小 3，并集大小 6，Jaccard = 0.5。单个 MinHash 碰撞的概率也是 0.5。

Q2用 b = 20、r = 5 做 LSH，阈值大约是多少？相似度 0.5 和 0.8 的碰撞概率分别是多少？

阈值 ≈ (1/20)^{1/5} ≈ 0.55。s = 0.5：s^5 = 0.03125，1 − (0.96875)^20 ≈ 0.47。s = 0.8：s^5 ≈ 0.328，1 − (0.672)^20 ≈ 0.9996。

Q3为什么 GPT-3 按 Pareto 分布随机保留文档，而不是用一个硬阈值？

硬阈值会系统性地删掉所有“不像参考文本”的内容，使数据过于单一。随机保留让高分文档大概率保留，低分文档也有小概率保留，维持了多样性，同时整体偏向高质量。

Q4数学数据 20B token，网页 10T token。训练 2T token，希望数学占 10%，数学要重复几个 epoch？用 UniMax 上限 C = 4，数学最多能占多少比例？

0.1 × 2T / 20B = 10 个 epoch。上限 4 个 epoch：p × 2T ≤ 4 × 20B → p ≤ 4%。

Q5为什么在小规模上找到的最优配比，直接用到大规模训练可能出问题？怎样修正？

小规模训练 token 少，稀缺的高质量数据不会重复，所以最优配比会重押高质量数据；大规模时同样的配比会让它重复很多 epoch 而过拟合。修正方法是模拟 epoch：按大小规模的训练量之比下采样所有数据源，让小规模实验面对和大规模相同的重复次数。
