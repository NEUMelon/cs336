01从第一性原理出发

第一性原理

自回归生成必须串行：第 t+1 个 token 依赖第 t 个 token，所以生成阶段不能像训练那样沿序列并行。每一步只处理每个序列的 1 个新 token。

每一步都要读一遍全部权重和 KV cache，但每个权重只参与 B 次（batch 大小）乘加。所以生成阶段的算术强度约为 B，而 H100 需要约 295 才能跑满算力。只要 B 不够大，推理就是 memory-bound 的。

推论：推理的耗时 ≈ 需要读取的字节数 ÷ 显存带宽。一切加速方法要么减少要读的字节（更小的 KV cache、更低的精度、更小的模型），要么让每次读取做更多事（更大的 batch、一次验证多个 token 的投机采样），要么更好地管理显存（分页、共享前缀）让 batch 变大。

02推理的全景

推理出现在很多地方：实际使用（聊天机器人、代码补全、智能体、批量数据处理）、模型评测（如指令遵循）、强化学习（采样大量生成，再打分）。

为什么效率重要：训练是一次性成本，推理会重复很多次。OpenAI 每天处理约 8.6T token；作为对比，DeepSeek V4 的训练数据是 32T token。聊天场景中大部分 token 是给人看的（人是瓶颈）；而智能体是“查询 → 内部推理轨迹 → 给人的输出”，生成的 token 数可以无限增长。生成的 token 数就是花掉的算力。

  • 做推理的公司：闭源模型提供方（OpenAI、Anthropic、Google 等），开放模型托管方（Together、Fireworks、Baseten、DeepInfra、Groq、Cerebras 等）。
  • 开源推理引擎：vLLM（伯克利，首创 PagedAttention，流行的默认选择）、SGLang（伯克利，首创 RadixAttention，适合智能体负载）、TensorRT-LLM（NVIDIA，针对 GPU 深度优化）、llama.cpp（纯 C++，支持 CPU，可本地运行）。

“快”是什么意思

指标含义关心它的场景
首 token 时间（TTFT）用户等多久才看到第一个 token交互式应用
延迟（秒/token）对单个请求，token 出现得多快交互式应用
吞吐（token/秒）对很多请求，总共生成得多快批处理

训练（监督）时能看到所有 token，可以沿序列并行（Transformer 里就是矩阵乘法）；推理时必须顺序生成，无法沿生成方向并行，所以更难用满算力。

03推理的算术强度

记号（类似 einops）：B = batch，T = 序列，D = 模型维度，H = 头维度，F = 4D（MLP 上投影维度），D = N·H（N 个头），N = K·G（GQA：K 组），S = 条件 token 数。

回顾：一次矩阵乘法

X (B×D) 乘 W (D×F)，bf16：读 X 2BD 字节、读 W 2DF 字节、写 Y 2BF 字节；FLOPs = 2BDF。

强度 = BDF / (BD + DF + BF)

当 B 远小于 D 和 F 时，强度 ≈ B。H100 的加速器强度约 295，所以当且仅当 B > 295 时是 compute-bound。极端情况 B = 1（矩阵乘向量）：强度为 1，读了整个 D×F 矩阵却只做 2DF 次运算。推理基本上就是这种情况。

KV cache

朴素推理：每生成一个 token，都把全部历史重新喂进 Transformer。一次前向是 O(T²)，生成 T 个 token 就是 O(T³)。但大量计算在前缀之间是可以共享的：把每个序列（B）、每个 token（S）、每一层（L）、每个 KV 头（K）的 H 维 key 和 value 向量存在 HBM 里，这就是 KV cache。

推理的两个阶段：

  1. Prefill：给定 prompt，编码成向量（像训练一样可并行）；
  2. 生成（decode）：逐个生成新 token（串行）。

MLP 层

SwiGLU MLP：读 X (B×T×D)，读 W_up、W_gate、W_down（共 6DF 字节），算 U、G 并写回，算 Y 并写回。

FLOPs = 6BTDF；字节 = 4BTD + 4BTF + 6DF。当 BT 远小于 D、F 时：

强度 ≈ B·T

  • Prefill：让 B·T 足够大（大 batch、长序列）就能 compute-bound。
  • 生成：两个问题：一次只生成一个 token（T = 1）；B 是并发请求数，对交互式应用来说不可预测。

注意力层

用 FlashAttention，只看矩阵乘法。S 为已有 token 数，T 为本次要算的 token 数。读 Q (B×T×D)、K 和 V (B×S×D)，写 Y (B×T×D)：

FLOPs = 4BSTD；字节 = 4BSD + 4BTD。

强度 = ST / (S + T)

  • Prefill（T = S）：强度 = S/2，很好。
  • 生成（T = 1）：强度 = S/(S+1) < 1，很差。
关键区别注意力的强度与 B 无关，所以增大 batch 也救不了它。原因：MLP 层中所有序列共用同一套权重（W 不依赖 B），批处理可以分摊读取权重的成本；注意力层中每个序列都有自己的 KV cache（Q、K、V 都依赖 B），没有东西可以分摊。

04延迟与吞吐

既然推理是 memory-bound 的，就可以算出理论上的延迟和吞吐。假设计算与访存完美重叠、忽略其他开销：

参数量 = 2VD + 3DF·L + (2DNH + 2DKH)·L（嵌入与输出层、MLP、注意力投影）

每序列 KV cache = S × K × H × L × 2（K 和 V）× 2（bf16） 字节

总显存 = B × 每序列 KV cache + 2 × 参数量

延迟 = 总显存 ÷ 显存带宽（每步都要把参数和 KV cache 全读一遍）

吞吐 = B ÷ 延迟（每步并行生成 B 个 token）

以 Llama 2 13B 在 H100 上为例（S = 1024，D = 5120，F = 13824，40 个头，头维度 128，40 层，词表 32000）：

配置参数每序列 KV总显存延迟/步吞吐
MHA，B = 113.0B0.84 GB26.9 GB8.0 ms125 tok/s
MHA，B = 6413.0B0.84 GB79.7 GB23.8 ms2,689 tok/s
MHA，B = 25613.0B0.84 GB240.8 GB71.9 ms3,562 tok/s
GQA（K = 8），B = 6411.3B0.17 GB33.4 GB10.0 ms6,417 tok/s
GQA（K = 8），B = 25611.3B0.17 GB65.6 GB19.6 ms13,068 tok/s

MHA 下 B = 256 需要 241 GB，H100 的 80 GB 放不下，而且吞吐的增长也在递减。

  • 增大 batch 使延迟变差：KV cache 是 O(B) 的，要读写的更多。
  • 增大 batch 使吞吐变好：读取参数的成本被分摊了。

于是有延迟与吞吐的权衡：小 batch 延迟好、吞吐差；大 batch 吞吐好、延迟差。

简单的并行：启动 M 份模型副本，延迟不变，吞吐变为 M 倍。困难的并行：把模型和 KV cache 切分到多张卡上。

TTFT 基本由 prefill 时间决定。所以 prefill 用小 batch 以缩短 TTFT，生成阶段用大 batch 以提高吞吐。

05有损捷径一：缩小 KV cache

显存是推理的瓶颈，那就缩小 KV cache，同时确保不损失太多精度。

分组查询注意力（GQA）

N 个 query 头，但只有 K 个 key/value 头，每个 KV 头服务 N/K 个 query 头。MHA：K = N；MQA：K = 1；GQA：K 介于两者之间。GQA 把 KV cache 缩小 N/K 倍。由于推理是 memory-bound 的，显存用量减少就直接带来加速（见上表：K 从 40 降到 8，同样 B = 64 下吞吐提高约 2.4 倍，而且放得下更大的 batch）。Ainslie et al. (2023) 验证了精度基本不降。

多头潜在注意力（MLA）

普通注意力的 KV cache 存的是 K = W_K h、V = W_V h（N·H 维）。MLA 只存压缩向量 c = W_c h（C 维），需要时再投影回 K = W_K c、V = W_V c。DeepSeek V2 把 N·H = 16384 压缩到 C = 512。麻烦在于 MLA 与 RoPE 不兼容，需要额外 64 维来承载 RoPE，共 576 维。精度方面：MHA 比 GQA 好（但更贵）；MLA 比 MHA 还略好（而且便宜得多）。

跨层注意力（CLA）

GQA 在头之间共享 KV，CLA 在层之间共享 KV。实证上改善了精度与 KV cache 大小（即延迟与吞吐）之间的帕累托前沿。

局部（滑动窗口）注意力

只看局部上下文，因为局部信息对建模最重要。有效上下文随层数线性增长（每层往回看 w 个 token，L 层就能看到 L·w 远）。KV cache 的大小与序列长度无关。问题是仍可能伤害精度；解决办法是局部层与全局层交替（混合层）。

DeepSeek V4 的注意力

支持 100 万 token 的上下文，组合了三种机制：压缩稀疏注意力（CSA，每 m 个 token 压缩成 1 个）、DeepSeek 稀疏注意力（DSA，选出 top-k）、重度压缩注意力（HCA，压缩得更狠）。

小结：目标是缩小 KV cache 而不伤精度。方法有低维 KV cache（GQA、MLA、CLA）、在部分层上用局部注意力截断 KV cache，以及线性注意力/状态空间模型（Mamba 2、Gated DeltaNet）、扩散模型等其他思路。

06有损捷径二：量化

降低数值精度：内存更少，延迟和吞吐就更好（因为 memory-bound），当然要关心精度。

机制：x_quant = round(x / scale) + zero_point，x ≈ (x_quant − zero_point) × scale。

例：x = 5.2342，scale = 0.1，zero_point = 4 → x_quant = 52 + 4 = 56 → 反量化得 5.2，误差 0.0342。

  • 量化感知训练（QAT）：训练时在前向里做“量化再反量化”，模拟量化误差。优点是权重学会适应量化；缺点是需要昂贵的大规模训练。
  • 训练后量化（PTQ）：训练后做，便宜得多。在样本数据上跑一遍，为每层或每个张量确定 scale 和 zero point。GPTQ 利用 Hessian 信息，调整尚未量化的权重来补偿已量化权重的误差。
  • 激活感知量化（AWQ）：观察到某些激活通道特别大，与它们相乘的权重更重要，所以根据激活值挑出 0.1–1% 的权重保留高精度。fp16 → int3，显存降为 1/4，速度提升 3.2 倍。

07有损捷径三：剪枝与蒸馏

把昂贵模型的一部分直接拆掉，让它变便宜，然后再修好它。NVIDIA 的做法（Minitron）：

  1. 在一个小的校准数据集（1024 个样本）上识别重要的层、头、隐藏维度；
  2. 去掉不重要的部分，得到更小的模型；
  3. 把原模型蒸馏到剪枝后的模型里。

结果：用很少的训练 token，就能得到与从头训练的同尺寸模型相当甚至更好的小模型。

两种得到快模型的配方：

从头训练蒸馏
1. 定义更快的模型架构
2. 训练这个更快的模型		1. 定义更快的模型架构
2. 用原模型（架构不同）的权重初始化
3. 通过蒸馏修复这个更快的模型

08无损捷径：投机采样

回忆两个阶段：prefill 并行编码整个序列（compute-bound，而且顺便给出每个位置的概率）；生成一次一个 token（memory-bound）。也就是说，检查比生成快。

  • 用一个便宜的草稿模型 p 猜几个 token（比如 4 个）；
  • 用目标模型 q 并行评估这些 token，看起来不错就接受。

这是以 p 为提议分布、q 为目标分布的改进版拒绝采样。改动之处是：总会至少产出一个 token（标准拒绝采样会一直循环）。关键性质：保证是来自目标模型的精确样本。

算法（每个位置）：从 p 采样 x。以概率 min(1, q(x)/p(x)) 接受；若拒绝，就从残差分布 norm(max(q − p, 0)) 重新采样，并丢弃后面所有草稿 token。

用例子证明：词表只有 {A, B}。设 p(A) > q(A)（草稿模型过度采样 A），于是 p(B) < q(B)。残差 max(q − p, 0) = [0, q(B) − p(B)]，归一化后为 [0, 1]。

P[得到 A] = p(A) · q(A)/p(A) + p(B) · 1 · 0 = q(A)

P[得到 B] = p(B) · 1 + p(A) · (1 − q(A)/p(A)) · 1 = p(B) + p(A) − q(A) = q(B)

（第二行用了 p(A) + p(B) = 1 = q(A) + q(B)。）两个概率都恰好等于目标分布。

实践中常见的组合：目标 70B + 草稿 8B，或目标 8B + 草稿 1B。草稿模型越接近目标模型越好（可以用蒸馏）。改进草稿模型的扩展：

  • Medusa：草稿头并行生成多个 token；
  • EAGLE：草稿模型利用目标模型的高层特征。

小结：数学保证了从目标模型精确采样；它利用了检查与生成之间的不对称；草稿模型还有大量创新空间（需要训练）。

09应对动态负载

在线服务中对序列做批处理很棘手：① 请求到达时间不同（等凑满一批对先到的请求不公平）；② 序列有共享前缀（系统提示、对同一问题采样多次）；③ 序列长度不同（填充很浪费）。

连续批处理（Orca）

问题一：训练时拿到的是一个致密的 token 块（batch × 序列长度）；推理时请求在不同时间到达和结束，是一个参差不齐的数组。

解法：迭代级调度。一步一步解码，新请求到达时直接加入当前 batch，不必等整批生成完。

问题二：批处理似乎要求所有序列形状一致，但每个请求长度不同。

解法：选择性批处理。注意力部分每个序列单独处理（形状如 [3, H]、[9, H]、[5, H]）；非注意力部分（MLP、投影）把所有序列拼接成 [3 + 9 + 5, H] 一起算。这正好对应第 3 节的结论：MLP 能从批处理中获益，注意力不能。

PagedAttention（vLLM）

以前的做法：请求到来时，为 prompt 和回复预先分配一段连续的 KV cache（按最大长度）。问题是碎片化，就像硬盘一样：

  • 实际生成的 token 可能远少于最大长度（内部碎片）；
  • 各段之间还可能有用不上的空隙（外部碎片）。

解法（借鉴操作系统的分页）：把一个序列的 KV cache 切成不连续的块，用块表把逻辑块映射到物理块。

  • 多个序列可以共享 KV cache：共享系统提示；对同一个 prompt 采样多个回复（例如程序合成）。
  • 在块级别共享前缀，并用写时复制处理分叉。

vLLM 的其他优化：融合块读取和注意力的 kernel（减少 kernel 启动开销）；使用最新的 kernel（FlashAttention、FlashDecoding）；用 CUDA graphs 避免 kernel 启动开销。

小结：用操作系统的思想（分页）来管理动态负载下的显存。

10本课要点

  • 推理很重要：实际使用、评测、强化学习都离不开它。
  • 它与训练的特性不同：生成阶段是 memory-bound 的，负载是动态的。
  • MLP 的生成强度约为 B，可以靠批处理提升；注意力的生成强度 < 1，只能靠缩小 KV cache。
  • 技术：新架构（GQA、MLA、局部注意力）、量化、剪枝与蒸馏、投机采样。
  • 来自系统领域的思想：投机执行、分页。
  • 新架构在推理效率上还有巨大的改进空间。

11自测题

Q17B 模型、bf16、H100（3.35 TB/s），batch = 1、忽略 KV cache，理论上每秒最多生成多少 token？

每步读 14 GB 权重，14 / 3350 ≈ 4.2 ms，约 240 token/s。这是上限，实际还会受 KV cache、kernel 开销影响。

Q2为什么增大 batch 能提高 MLP 的算术强度，却不能提高注意力的？

MLP 的权重被 batch 中所有序列共享，读一次可以服务 B 个 token，强度约为 B。注意力要读的是每个序列自己的 KV cache，数据量随 B 线性增长，计算量也随 B 线性增长，比值与 B 无关。

Q3投机采样中，如果草稿模型和目标模型完全一样，会怎样？如果完全不相关呢？

完全一样：接受概率 min(1, q/p) = 1，每轮 k 个草稿全部接受，外加目标模型顺带给出的 1 个 token。完全不相关：几乎每次第一个草稿就被拒绝，每轮只从残差分布得到 1 个 token，还白白付出了草稿模型的成本。两种情况下，输出分布都严格等于目标模型。

Q4用 scale = 0.05、zero_point = 0 把 x = 5.2342 量化成 int8，再反量化，结果是多少？

round(5.2342 / 0.05) = round(104.68) = 105，在 [−128, 127] 内。反量化 105 × 0.05 = 5.25，误差 0.016，比讲义例子更小，但能表示的范围只有约 ±6.4。

Q5PagedAttention 解决了什么问题？它和操作系统的虚拟内存有什么对应关系？

解决按最大长度预分配连续显存带来的内部和外部碎片，并支持前缀共享。对应关系：KV 块 ↔ 内存页；每个序列的块表 ↔ 页表；共享前缀 + 写时复制 ↔ fork 后的共享页。显存利用率提高，能同时服务的序列更多，batch 更大，吞吐更高。
