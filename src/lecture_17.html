01从第一性原理出发

第一性原理

Transformer 处理的是 token 序列（离散的或连续的），每个 token 代表大约一个语义单位的信息。所以任何模态都必须先被切成 token。文本也是如此（回忆第一课的分词），只是非文本模态更难。

分词的两个老问题在这里重新出现：

  • 序列长度：一张 336×336 的图切成 14×14 的小块就有 576 个 token，一段视频更多。注意力是平方复杂度，token 太多就太贵；太少就丢信息（例如文字识别需要高分辨率）。
  • token 表示什么：理解需要语义（这是一只猫）；生成需要能还原像素的细节。连续的语义特征（CLIP）适合理解，离散的可重建编码（VQ-VAE）适合生成，两者不一定兼得。

于是两个问题：① 怎样输入非文本数据（理解图像）？② 怎样输出非文本数据（生成音频、图像）？

02CLIP：用图文对学习图像表示

背景：计算机视觉模型过去在人工标注的图像上训练（如 ImageNet 的 120 万张图、1000 个类别）。问题：能否利用数量大得多的（图像，说明文字）对？

方法：对比学习

  1. 取一个 batch 的（图像，文本）对（例如 32768 对）；
  2. 分别编码每张图像和每段文本；
  3. 对每张图像，让它更偏好与之配对的文本，而不是其他文本；
  4. 对每段文本，让它更偏好与之配对的图像，而不是其他图像。

设图像嵌入 I_i、文本嵌入 T_j 都已 L2 归一化，温度 τ（可学习）。相似度矩阵 S_ij = I_i · T_j / τ 是 N×N 的，对角线是正确配对。

L = ½ [ CE(S, 对角线, 按行) + CE(Sᵀ, 对角线, 按行) ]

即对每一行（每张图）在 N 段文本上做 softmax 分类，对每一列（每段文本）在 N 张图上做 softmax 分类。batch 中其他样本都充当负例，所以需要很大的 batch，而且 softmax 要在整个 batch 上归一化。

数据与处理

搜索了 50 万个查询，每个查询约得到 2 万个图文对，共训练了 4 亿个图文对。数据集没有公开。OpenCLIP 复现了它（用 LAION-5B 数据集，而 LAION-5B 本身是用 CLIP 过滤的）。

图像处理：图像分辨率各不相同（任意 W×H），先用双三次插值缩放使短边为 336 像素，再中心裁剪（切掉边缘）得到 336×336。

编码器

  • 视觉编码器：试过 ResNet-50 和 Vision Transformer（ViT）。ViT 把图像切成固定大小的块，每块展平后线性投影成一个 token。用注意力池化：以激活的全局平均作为 query 做一次 QKV。最好的模型是 ViT-L/14@336px（Large 规模，14×14 的块，3 个颜色通道，在 336×336 图像上训练）。
  • 文本编码器：GPT-2 式 Transformer（6300 万参数，12 层），编码 [BOS] … [EOS]，取最高层 [EOS] 位置的激活。
补充：一张图是多少个 token

336 / 14 = 24，所以一张图是 24 × 24 = 576 个块，也就是 576 个 token。分辨率翻倍，token 数变为 4 倍。

结果

在 ImageNet 上，零样本 CLIP（把类别名写成“a photo of a {类别}”，选相似度最高的）胜过在 120 万张 ImageNet 图上训练的 ResNet-50。

消融：另一种做法是直接从图像预测文本（生成式），但计算效率比 CLIP 式的排序低得多。预测具体的字词太难了，只需要判断“哪段文本配哪张图”就简单得多。

小结：图像编码捕获了（带噪声的）文本所给出的语义；设计决策是根据图像分类选的（不太精细）；技术上需要很大的 batch，并在整个 batch 上做 softmax。

03SigLIP：换成 sigmoid 损失

目标
CLIP多分类：对（文本，图像）与所有（文本，其他图像）比较，softmax
SigLIP二分类：这一对（文本，图像）是否匹配？对每一对独立做 sigmoid

L = −(1/N) Σ_i Σ_j log σ( z_ij · (t · I_i·T_j + b) )，其中 z_ij = +1（i = j，匹配）或 −1（不匹配），t 是可学习的温度，b 是可学习的偏置（初始化为较大的负数，因为绝大多数对都不匹配）。

每一对的损失互相独立，不需要对整个 batch 做归一化。所以可以把 batch 切到多个设备上，各自计算本地的块，再轮换文本嵌入，不需要一次汇总全部相似度矩阵。

数据：WebLI 数据集，数十亿量级的图文对，从互联网抓取，用自动 OCR 提取图像中的文字，只保留质量最高的 10%，支持 100 种语言。

效率：CLIP 在 256 块 TPUv3 上训练 10 天；SigLIP 在 32 块 TPUv4 上训练 5 天（TPUv4 的 FLOP/s 还比 TPUv3 低），快得多。

批大小：把 batch 大小和损失解耦。batch 小于 16K 时比 CLIP 好；可以扩展到 100 万的 batch，但 32K 就够了。

04LLaVA：把图像编码接进 LLM

LLaVA（Large Language and Vision Assistant）：视觉编码器用 CLIP，文本解码器用 Vicuna（在 ShareGPT 对话上微调的 LLaMA）。

数据：用 GPT-4 合成

MS COCO 的图像带有边界框和 Mechanical Turk 写的说明。把说明文字或检测到的物体（纯文本！）交给 GPT-4，让它生成问题或对话，再把生成内容和原图配对。共 15.8 万个样本。GPT-4 并没有看到图像，只看到了关于图像的文字描述。

模型与训练

用 CLIP（ViT-L/14）编码图像，然后用一个线性投影 W 映射到 LLM 的嵌入空间（Flamingo、Q-Former 等方案更复杂）。图像 token 和文本 token 拼在一起送进 LLM。

阶段冻结训练目的
1. 对齐视觉编码器、语言模型只训练 W让图像特征落进 LLM 能“读懂”的嵌入空间
2. 微调视觉编码器W 和语言模型学会基于图像进行对话

05LLaVA-OneVision：多图、视频与高分辨率

LLaVA 系列的最新版本（在 LLaVA 1.5、LLaVA-NeXT 之后），能处理多张图像和视频。视觉编码器：SigLIP（使用最后一层 Transformer 前后的网格特征）；文本解码器：Qwen-2 72B；投影器：2 层 MLP。

AnyRes：保留高分辨率

保留高分辨率很重要（例如 OCR）。CLIP 把图缩放并裁剪到 336×336，会丢失信息。解决办法 AnyRes（LLaVA 1.5 引入）：把图像切成 a × b 块（每块与视觉编码器的分辨率匹配），分别编码后拼接；如果 token 太多（原图分辨率太高），就用双线性插值缩减。

平衡三种输入

目标：让所有输入类型产生大致相同长度的 token 序列。

  • 单张图像：用更高的分辨率；
  • 多张图像：每张用基础分辨率；
  • 视频：每帧用更低的分辨率。

数据理念：质量重于数量。训练理念：从易到难。

模态之间的迁移

  • 单图数据中的图表、示意图能力，泛化到多图场景；
  • 单图上的 OCR 加上多图上的关系推理，泛化到基于 GUI 的智能体；
  • 单图上的视觉提示（画圈标注），泛化到视频。

小结：标准的视觉语言模型模板是“视觉编码器 + 投影器 + LM”；大部分工作花在数据整理上（大量合成的、针对具体任务的数据）；完全开源（发布了权重和数据）。

06Qwen-VL 系列

Qwen-VL

  • 视觉编码器：OpenCLIP 的 ViT-bigG（14×14 块）。
  • 适配器：一层交叉注意力，融入二维位置编码，把图像特征压缩到固定长度 256。
  • 特殊 token：<img>、<box>、<ref>（用于定位和指代）。
阶段数据训练哪些参数
1大规模、低质量的图文对冻结 LM，训练视觉编码器 + 适配器
2更高质量的任务数据，提高分辨率训练全部参数
3指令微调数据冻结视觉编码器，训练适配器 + LM

Qwen2-VL

更大的 ViT（6.75 亿参数）。关键是动态分辨率：不再把图缩放到固定尺寸，而是按原始分辨率切块。

一块 224×224 的区域，用 14×14 的块切成 16×16 = 256 个块；再把相邻 2×2 个块合并成一个 token，得到 8×8 = 64 个 token，加上视觉开始和结束的两个特殊 token，共 66 个 token。

视频：每秒采样 2 帧，最多 16384 个 token。

多模态旋转位置编码（MRoPE）：把 RoPE 的维度分成三份，分别编码时间、高度、宽度三个位置分量。文本 token 的三个分量相同，退化为普通 RoPE；图像 token 的时间分量固定、高宽分量取块的坐标；视频 token 的时间分量随帧递增。这样模型直接“知道”每个视觉 token 在时空中的位置。

语言模型用 Qwen2 初始化，视觉编码器用 DFN 初始化。训练与 Qwen-VL 类似的三阶段。能力覆盖很广：文档理解、多语言 OCR、视频理解、智能体操作等。

Qwen3-VL

  • 语言模型：Qwen3（稠密和 MoE，最大 235B-A22B），支持 256K 长上下文。
  • 视觉编码器：SigLIP-2（架构与 SigLIP 相同）。
  • 交错式 MRoPE：把时间、宽、高三个轴交错分配到低频和高频维度上，即 [t w h t w h …]，而不是 [t t t … w w w … h h h …]。原来的分法让时间轴只占高频（或低频）部分，交错后每个轴都能覆盖全部频率范围。
  • 显式视频时间戳：用单独的文本 token 表示时间，而不是塞进位置编码。
  • 平方根归一化的逐 token 损失：平衡文本和多模态数据（视频样本很长，不希望它们主导损失）。
  • 适配器 DeepStack：跨层融合，把视觉信息注入 LLM 的多个层，而不只是输入层。
  • 训练：预训练 4 个阶段（先训练适配器，再在 8K、32K、256K 长度上训练全部参数）；后训练：长思维链 SFT、知识蒸馏、RL。

小结：性能达到最强水平；大量数据工作但细节不多；架构上有一些小但可能重要的改进；规模放大。

07Chameleon：一切都是离散 token

到目前为止，视觉语言模型都是用 CLIP 或 SigLIP 编码图像再注入 LM。缺点：不能生成图像（需要另接扩散模型）。

Chameleon 把一切都映射成离散 token。好处：可以用统一的方式理解和生成图像，图像和文本可以任意交错（早期融合）。

VQ-VAE 图像分词器

关键区别：编码器必须输出离散 token，这样才能像文本一样生成。

VQ-VAE：编码器把图像映射成一个特征网格；每个位置的特征向量被替换成码本（codebook）中最近的那个向量，记下它的编号，这个编号就是 token；解码器从码本向量还原图像；训练目标是最小化重建误差（外加让编码器输出贴近码本的承诺损失）。

Chameleon：把 512×512 的图像编码成 1024 个 token（32×32 网格），码本大小 8192。

补充估算：每个 token 携带 log₂ 8192 = 13 比特，1024 个 token 共约 1.7 万比特；原图 512×512×3 个 8 位像素约 630 万比特。压缩了约 400 倍，所以细节（例如小字）必然丢失。

此外，他们还在文本和图像 token 上训练了一个新的 BPE 分词器。

训练

  • 阶段 1（80%）：大规模无监督数据：2.9T 纯文本 token、1.5T 图文 token、400B 图文交错 token。
  • 阶段 2（20%）：一半是阶段 1 的数据，一半是高质量数据。

训练稳定性

文本 token 熵低（下一个词往往很确定），图像 token 熵高（纹理细节难以预测）。两种模态在同一个模型里竞争，导致范数增长和 logit 漂移。修复办法正是第三课讲过的稳定性技巧：QK-norm 和 z-loss。

小结：优雅（只是对离散 token 做自回归建模）；性能不如连续编码（离散化丢失信息，比如 OCR）；多模态联合训练很棘手。

08本课要点

  • 前沿模型被期望是多模态的（原生多模态、全模态）。
  • 根本挑战：怎样编码非文本模态，即怎样把它们变成 token。
  • 理解和生成的需求可能不同：理解要语义，生成要更细的细节。
  • 要平衡图像、视频（信息密度较低、序列很长）与文本，以保证训练稳定。
  • 当前主流：连续编码器 + Transformer 用于理解，扩散模型用于生成；统一离散 token（Chameleon）优雅但有信息损失。
  • 标准模板：视觉编码器（CLIP/SigLIP）+ 投影器 + LM，分阶段训练，大部分功夫在数据上。

09自测题

Q1ViT-L/14 处理一张 448×448 的图，有多少个 token？如果用 Qwen2-VL 的 2×2 合并呢？

448 / 14 = 32，32 × 32 = 1024 个块 token。2×2 合并后为 16 × 16 = 256 个（再加两个特殊 token）。

Q2CLIP 为什么需要很大的 batch？SigLIP 为什么不那么需要？

CLIP 的负例就是同一 batch 中的其他样本，softmax 需要足够多的负例才能学到细粒度的区分，而且要在整个 batch 上归一化。SigLIP 对每一对独立做二分类，损失与 batch 大小解耦，小 batch 下表现更好，也更容易分布式计算。

Q3LLaVA 第一阶段为什么只训练投影矩阵 W？

视觉编码器和 LLM 都已经很强，但它们的表示空间不同。先只学一个投影，把图像特征对齐到 LLM 的嵌入空间，便宜且不会破坏两边已有的能力；对齐之后再联合微调 LM 学习多模态对话。

Q4为什么 Chameleon 这类离散 token 方法在 OCR 上吃亏？

VQ-VAE 以很高的压缩率（每个 token 13 比特代表一大块像素）把图像离散化，重建目标偏向整体外观，小字等高频细节被丢掉。连续编码器（配合高分辨率切块）能保留更多细节。

Q5为什么多模态训练要特别注意平衡视频数据？

视频产生的 token 极多，但每个 token 的信息密度低（相邻帧高度相似）。如果按 token 平均损失，视频会主导梯度，挤占文本能力。Qwen3-VL 用平方根归一化的逐样本损失、LLaVA-OneVision 用降低视频帧分辨率，都是在平衡各模态的贡献。
