01从第一性原理出发

第一性原理

多机扩展想要三样东西：

  1. 显存线性扩展：能放下的最大模型参数量随 GPU 数线性增长；
  2. 算力线性扩展：模型 FLOPs 随 GPU 数线性增长；
  3. 简单的通信原语：只用 all-reduce、reduce-scatter、all-gather、all-to-all 等集合操作。

训练时占显存的东西可以分成两类：静态的（参数、梯度、优化器状态，与参数量成正比）和动态的（激活值，与 batch × 序列长度 × 层数成正比）。每种并行都是在决定：哪些东西要切分、切分后要通信什么（梯度、参数，还是激活值）、通信能不能和计算重叠。

新的计算单位是整个数据中心。

02网络基础

单卡扩展有极限：世界上最快的超级计算机有 exaFLOPs 级别的算力，而模型大到任何单张 GPU 都放不下。解决办法是节点内通过高速互连并行，节点间通过高速网络并行，把显存和计算需求分摊到许多 GPU 和机器上。

All-reduce = reduce-scatter + all-gather

这个分解很重要：在带宽受限的情况下，这已经是最好的做法。所以把 all-reduce 拆开几乎没有额外代价，却让我们可以在中间“只保留自己那一片”。

TPU 与 GPU 的网络设计

TPUGPU
拓扑环形网格（toroidal mesh），只连邻居全连接（通过 NVSwitch，最多约 256 张）
优点便宜，可以做得很快，适合张量并行这类规则的通信适合不规则的通信，如专家并行的 all-to-all

但情况在变：TPU8i 的网络更接近树形拓扑（可能是为了 MoE），TPU8t 的横向扩展网络（Virgo）用交换网络。为什么不把所有卡直接连起来？一个全连接域越大，交换设备和线缆越贵（例如华为 CloudMatrix 384 与 NVIDIA GB200 NVL72 的对比）。

03数据并行与 ZeRO

朴素数据并行

从 SGD 出发：θ_{t+1} = θ_t − η Σᵢ ∇f(xᵢ)。把大小为 B 的 batch 分给 M 台机器，每台算自己那份的梯度，再交换梯度同步。

  • 算力扩展：每张 GPU 处理 B/M 个样本。好。
  • 通信开销：每个 batch 传输 2 × 参数量。batch 大时可以接受。
  • 显存扩展：没有。每张 GPU 至少要存全部参数。

显存到底有多糟

混合精度 + Adam，每个参数需要 16 字节，相当于 5 份权重拷贝：

  • bf16 参数：2 字节
  • bf16 梯度：2 字节
  • fp32 主权重（SGD 真正累加更新的那份）：4 字节
  • fp32 Adam 一阶矩：4 字节（或 bf16 的 2 字节）
  • fp32 Adam 二阶矩：4 字节（或 bf16 的 2 字节）

后三项合称“优化器状态”，占了 16 字节中的 12 字节。

ZeRO 的核心想法：把昂贵的部分（状态）切分到各卡上，并利用 reduce-scatter + all-gather 的等价性。

ZeRO stage 1：切分优化器状态

每张卡仍有完整的参数和梯度，但只保存 1/N 的优化器状态，只负责更新对应那一片参数。

  1. 每张卡在自己的数据上算出完整梯度；
  2. 对梯度做 reduce-scatter：每张卡拿到自己负责那一片的梯度总和（通信量 ≈ 参数量）；
  3. 每张卡用自己的梯度片和状态片更新自己那片参数；
  4. 对参数做 all-gather：大家拿到完整的新参数（通信量 ≈ 参数量）。
朴素 DDPZeRO stage 1
通信原语一次 all-reduce（梯度）一次 reduce-scatter（梯度）+ 一次 all-gather（参数）
通信量2 × 参数量2 × 参数量
显存(4 + K) × 参数量(4 + K/N) × 参数量

（K 为每参数优化器状态的字节数。）通信量完全一样，在带宽受限的情况下，ZeRO-1 省下的显存是白送的。

ZeRO stage 2：再切分梯度

麻烦在于：我们永远不能实例化完整的梯度向量，但数据并行要求每张卡都计算完整的梯度。解决办法是逐层处理：

  1. 沿计算图逐层反向；每算完一层的梯度，立刻 reduce 发给负责它的卡；该层梯度在反向图中不再需要后，立即释放；
  2. 每张卡用自己的梯度片和状态片更新参数；
  3. all-gather 参数。

ZeRO stage 3（即 FSDP）：什么都切

连参数也切分。沿计算图前进时，按需请求参数，用完立即释放。

  • 前向：每层之前 all-gather 该层参数，算完释放；
  • 反向：再 all-gather 一次参数，算出梯度后 reduce-scatter，释放；
  • 通信量：2 次 all-gather（参数量）+ 1 次 reduce-scatter（参数量）= 3 × 参数量。

关键是通信与计算重叠：计算第 i 层时，预取第 i+1 层的参数。只要每层的计算时间比传一层参数的时间长，通信开销就被掩盖了。整个过程概念上很简单，写一个 FSDP 块包装器就行。

ZeRO 的代价DDP 通信 2 × 参数量。ZeRO-1 也是 2 倍，免费，应该总是开；ZeRO-2 也是 2 倍，几乎免费（忽略额外开销）；ZeRO-3 是 3 倍，多 50%，但也不算差（忽略延迟）。

ZeRO 实战：能放下多大的模型

假设除主权重外全部用 bf16（纯 bf16 训练配合 Kahan 求和是可行的），每参数 12 字节：bf16 参数 2 + bf16 梯度 2 + 状态 8（fp32 主权重 4 + 两个 bf16 矩各 2）。在 8 张 A100 80GB 上：

数据并行仍有的问题

  • 算力扩展：机器数不能超过 batch 大小，接近时通信开销很高；而且增大 batch 的收益递减（临界 batch size）。
  • 模型放不下：ZeRO-1、2 不能让显存随卡数扩展；ZeRO-3 原则上可以，但不减少激活值显存。

04模型并行

模型并行在不改变 batch 大小的前提下扩展显存：它像 ZeRO-3 一样把参数切分到各卡上，但通信的是激活值（ZeRO-3 通信的是参数）。三种切法对应三种模型并行：流水线并行、张量并行（+ 序列并行）、专家并行。

流水线并行（切深度）

朴素的按层并行：把层分给不同的 GPU，激活值和部分梯度来回传。利用率很差：n 张 GPU，每张只有 1/n 的时间在工作，其余时间在等反向传播传回来。

解决办法：处理多个 micro-batch。第一个 micro-batch 送走后，马上开始算第二个。

气泡时间 / 有效计算时间 = (n_stages − 1) / n_micro所以需要大 batch

流水线看起来很糟，为什么还用？

  1. 比 DDP 省显存；
  2. 通信性质好（相比 FSDP）：只传激活值（b × s × h），而且是点对点的。

所以一般在较慢的网络链路（节点之间）上用流水线并行，换取显存的扩展。性能高度依赖 batch 大小。

  • 更复杂的流水线调度（交错调度等）可以用更多的通信带宽换取更高的利用率。
  • 零气泡流水线：把反向拆成两部分：① 对激活值反传梯度（后续层在等它，要尽快做）；② 计算权重梯度（没人等，可以任何时候做）。用第 ② 部分去填气泡。

张量并行（切宽度）

观察：矩阵乘法可以分解成子矩阵，再把部分和加起来。

MLP：Z = GeLU(XA) B。

A 按列切：A = [A₁, A₂]。则 XA = [XA₁, XA₂]，GeLU 是逐元素的，所以 Y₁ = GeLU(XA₁)、Y₂ = GeLU(XA₂) 可以在两张卡上独立算，不需要通信。

B 按行切：B = [B₁; B₂]。则 Z = Y₁B₁ + Y₂B₂，每张卡算一个部分和，最后 all-reduce 一次。

记前后两个通信算子为 f 和 g：前向时 f 是恒等（输入 X 每张卡都有），g 是 all-reduce；反向时反过来，f 是 all-reduce（对 X 的梯度要把两张卡的贡献加起来），g 是恒等。

在一个 Transformer 块里：

  • 按列切：QKV 投影、上投影（up-projection）；注意力头天然可以分到不同卡上；
  • 按行切：注意力输出投影、下投影（down-projection）；
  • 复制：归一化层、路由器等。

于是每个注意力子层和每个 MLP 子层各只需前向一次、反向一次 all-reduce。在 GPU 上，张量并行通常只在一个节点内用（最多 8 张卡），因为需要高速互连。

张量并行流水线并行
气泡没有（网络够快就不用互相等待）有
复杂度低，容易包装已有模型高
对 batch 的要求不需要大 batch需要大 batch 来掩盖气泡
通信量每层 8bsh(n−1)/n，all-reduce每个 micro-batch bsh，点对点

结论：只要有低延迟、高带宽的互连，就用张量并行。

激活值显存与序列并行

最后一个复杂之处：显存是动态的。除了静态的参数，激活值也可能很大。张量并行和流水线并行能线性减少参数显存，但激活值呢？（Korthikanti et al., 2022）

每层激活值显存（s = 序列长度，b = batch，h = 隐藏维度，a = 头数，t = 张量并行度，16 位存储，单位字节）：

  • 全部存储：sbh (34 + 5as/h)。其中 5as/h 来自注意力的平方项（分数矩阵、softmax、dropout 掩码），可以像 FlashAttention 那样用重计算去掉。
  • 张量并行：sbh (10 + 24/t + 5as/(ht))。矩阵乘相关的激活被切分了，但剩下的 10 这一项没有：LayerNorm 的输入（4sbh）、dropout（2sbh）、注意力和 MLP 的输入（4sbh）。模型越大，这部分越成问题。
  • 张量并行 + 序列并行：sbh/t · (34 + 5as/h)，真正线性扩展。

序列并行的观察：那 10sbh 项全是沿序列逐位置的操作（LayerNorm、dropout），所以可以沿序列维度切分。在张量并行区域的入口和出口，把原来的通信算子换成：前向时 g 是 all-gather、ḡ 是 reduce-scatter，反向时反过来。all-reduce = reduce-scatter + all-gather，所以总通信量不变。

专家并行

不切矩阵乘法，而是把不同的专家放在不同的卡上，把激活值路由过去（all-to-all）。对 MLP 来说，专家并行的行为很像张量并行：需要高带宽、减少激活值显存；但切分矩阵乘法会降低单个 kernel 的效率，路由激活值则不会。

组合时的复杂之处：

  • 专家并行通常和数据并行共享副本（EP ≤ DP），数据并行与张量并行的组合可能降低利用率。
  • MoE 只作用在 MLP 上，注意力没有专家。注意力希望张量并行度高（因为不能用专家并行），MLP 希望张量并行度低（更愿意用专家并行）。解决办法是更灵活的并行策略：例如 Megatron 为注意力（TP/CP/DP）和 MLP（ETP/EP/EDP）分别设置并行度。

上下文并行 / Ring Attention

长序列时，把一条序列的激活值切分到多张卡上。每张卡持有一段 query，K/V 块沿环在卡之间轮转，配合在线 softmax 逐块累加注意力。

063D（4D）并行：怎么组合

经验法则

第一步，直到模型放进显存为止：张量并行 / 专家并行最多到单机 GPU 数；跨机器用流水线并行（或者视带宽用 ZeRO-3）。

第二步，直到用完所有 GPU：剩下的全用数据并行扩展。

如果 batch 太小，用梯度累积换取更大的 batch 和更好的通信效率。

决定性的量是每张 GPU 分到的全局 batch 大小：它太小时，任何并行方式的通信都掩盖不住。

Narayanan et al. (2021) 的扩展策略：张量并行先加到 8，然后封顶在 8；流水线并行随模型增大而增加，保证放得下；数据并行随规模逐渐减小，最大的模型 DP = 6。在 64 台机器上并行时，8 × 8（TP=8、PP=8）的配置最好。精心配置的 3D 并行，GPU 数量增加时单卡利用率保持平稳，也就是线性扩展。激活重计算的额外计算可以“自己付费”：它省下的显存允许更大的 batch，反而提高吞吐。

08本课要点

  • 超过一定规模，就必须多卡、多节点并行。
  • 没有单一的解决方案，通常三类并行（数据、模型、激活）都要用。
  • ZeRO-1/2 以不增加通信量的代价切分优化器状态和梯度；ZeRO-3 多 50% 通信，切分一切静态显存。
  • 流水线并行通信少但有气泡，适合跨节点；张量并行没有气泡但通信大，适合节点内。
  • 序列并行让激活值显存也线性扩展；专家并行是 MoE 的天然切法。
  • 组合的经验法则：TP/EP 到单机上限 → PP 放下模型 → 其余全部 DP。

09自测题

Q170B 模型、每参数 16 字节（混合精度 Adam），64 张 80GB GPU，只用数据并行。ZeRO-1、ZeRO-3 下每卡静态显存各多少？

总计 70B × 16 = 1120 GB。ZeRO-1：参数 2 + 梯度 2 + 状态 12/64 ≈ 4.19 字节/参数 → 约 293 GB，放不下。ZeRO-3：16/64 = 0.25 字节/参数 → 17.5 GB，放得下（激活值另算）。

Q2为什么说 ZeRO-1 是“免费的”？

DDP 的 all-reduce 本来就可以实现为 reduce-scatter + all-gather。ZeRO-1 只是在两步之间插入“只更新自己那片参数”，通信量仍是 2 × 参数量，却把优化器状态显存降到 1/N。

Q3推导 Megatron MLP 张量并行为什么只需要一次 all-reduce。

第一层按列切，GeLU 逐元素，所以各卡独立得到 Y 的不同列；第二层按行切，Z = Σ Yᵢ Bᵢ，各卡得到一个部分和，最后 all-reduce 一次求和。中间不需要任何通信。

Q4h = 8192、s = 4096、b = 1、a = 64，不做重计算、不做并行，一层激活值显存多少？注意力平方项占多少？

sbh = 4096 × 8192 ≈ 3.36×10⁷。34sbh ≈ 1.14 GB；5as/h = 5 × 64 × 4096 / 8192 = 160，160sbh ≈ 5.37 GB。平方项占了约 82%，这就是为什么 FlashAttention 式的重计算这么重要。

Q5为什么 MoE 模型里注意力和 MLP 想要不同的张量并行度？

MLP 可以用专家并行切分（效率高，不切矩阵乘），所以希望 TP 小；注意力没有专家，只能用 TP（或 CP）来切，所以希望 TP 大。统一一个 TP 值会让某一边吃亏，于是 Megatron 为两部分分别设置并行度。
