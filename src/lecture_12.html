01从第一性原理出发

第一性原理

评测看起来是个机械流程：定义一些 prompt → 发给模型拿回回答 → 计算准确率。但它其实是一个深刻而重要的话题，它塑造了 AI 的发展方向：大家会朝着被测量的东西优化。

核心挑战：抽象的构念 → 具体的指标。“聪明”“有用”“安全”都是抽象构念，任何一个具体指标都只是它的一个近似。所以每个评测都要回答三个问题：

  • 难度：能不能区分出强模型和弱模型（还没饱和）？
  • 现实性：它和真实使用有多接近（生态效度）？
  • 有效性：分数是否真的反映了能力，而不是污染、数据错误或投机取巧？

没有唯一正确的评测，它取决于你想回答什么问题。

什么样的模型算好？可以有很多种回答：

  • 在基准上表现好（如 Artificial Analysis 的综合榜单）；
  • 在基准上表现好而且运行便宜（性能—成本图）；
  • 人们更喜欢它的回答（Arena AI，原 Chatbot Arena）；
  • 人们实际选择使用并为它付费（OpenRouter 的使用量排行）。

02困惑度

回忆：语言模型是 token 序列上的概率分布 p(x)。困惑度衡量 p 是否给数据集 D 赋予了高概率：

PPL = (1 / p(D))^{1/|D|} = exp( −(1/|D|) Σᵢ log p(xᵢ | x<ᵢ) )即平均每个 token 的交叉熵取指数
补充：怎么理解困惑度

困惑度 k 可以理解为：模型在每一步平均相当于在 k 个等可能的选项中犹豫。均匀猜测词表 V 个 token 时困惑度就是 V；完全确定时是 1。它和训练损失（交叉熵）只差一个 exp，所以随规模平滑下降，这正是 scaling law 用它的原因。注意困惑度只能在同一个 tokenizer 下比较：切得越细，每个 token 越好预测，困惑度越低，但这不代表模型更好。

预训练就是在训练集上最小化困惑度，自然的做法是在测试集上测困惑度。传统语言模型研究就是这么做的。标准数据集：Penn Treebank（华尔街日报）、WikiText-103（维基百科）、One Billion Word Benchmark（来自机器翻译 WMT11：欧洲议会、联合国、新闻）。

经典范式：分布内评测，在某个数据集的训练集上训练、测试集上评测。例如纯 CNN + LSTM 在 One Billion Word 上把困惑度从 51.3 降到 30.0。

GPT-2 改变了范式：在 WebText（40 GB，Reddit 链接的网页）上训练，然后零样本地在标准数据集上评测（分布外评测）。在小数据集（PTB）上效果更好，因为迁移有帮助；在大数据集（1BW）上则不如专门训练的模型。

“困惑度就是你需要的一切”

这更多是信念而非科学：设真实分布为 t，模型为 p。最好的困惑度是 H(t)，当且仅当 p = t 时达到。如果 p = t，那所有任务都解决了：只要计算 p(答案 | 问题)。所以不断压低困惑度，最终就能“达到 AGI”。

但困惑度也可能“多于你需要的”：例如 Stanford was founded in 1885，困惑度惩罚对所有 token 的预测，其中一些（如 founded）可能与你关心的无关。解决办法是测条件困惑度 p(回答 | 提示)^{1/|回答|}。

伪装成困惑度的基准

  • 完形填空：LAMBADA，需要读完整段上下文才能预测最后一个词。
  • 多选句子补全：HellaSwag，比较模型对 4 个候选续写的概率，选概率最高的。

警告（如果你要办困惑度排行榜）：参赛者提交 LM，你计算 log_prob = LM(test_data)，你必须信任这些概率是合法的（和为 1）。一个作弊的模型可以不归一化，给每个 token 都报高概率。而下游任务只需 response = LM(prompt)，在回答上算准确率，没有这个问题。

小结：困惑度仍然在语言模型开发中大量使用（scaling law 很平滑），但我们仍需要能反映真实场景的基准（为了说服不信者）。

03考试类基准

考试是测试语言模型的好办法（和测试人一样）：可以控制科目和难度，可以设计成答案明确、容易评分。

基准内容要点
MMLU（2021）57 个科目（数学、美国历史、法律、道德等），多选题由研究生和本科生从网上免费资源收集。名字叫“语言理解”，其实测的是知识。最初在 GPT-3 上用少样本提示评测
MMLU-ProMMLU 去掉噪声和过于简单的题选项从 4 个扩展到 10 个；用思维链评测（给模型更多机会）；模型准确率下降 16–33%，不那么饱和了
GPQA由 61 位 Upwork 上的博士外包人员编写博士专家准确率 65%；非专家可用 Google 30 分钟也只有 34%；GPT-4 为 39%。“防谷歌”：搜不到答案
Humanity's Last Exam2500 题，多模态，多学科，多选 + 简答设立 50 万美元奖金池并给出题人署名；先用前沿 LLM 过滤（它们答对的题被剔除），再经多轮人工审核

小结：随着模型进步、现有基准饱和，题目越来越难；多选格式可以要多难有多难；但它不反映真实使用（开放式、不一定有标准答案）。

04对话类基准

大多数人不会问 AI 助手多选题。例如：“我想做一道山羊奶酪甜菜沙拉，哪些香草搭配合适，哪些不合适？”这种开放式回答怎么评？

Chatbot Arena（Arena AI）

数据收集：随便一位网友输入 prompt → 拿到两个随机匿名模型的回答 → 选出更好的那个。然后根据两两比较计算 Elo 分：

P(A 胜 B) = 1 / (1 + 10^{(Elo_B − Elo_A)/400})拟合这个模型，使观察到的两两比较结果概率最大

这就是 Bradley–Terry 模型：每个模型有一个强度参数，胜率只取决于强度之差。Elo 相差 100 分时，P = 1/(1 + 10^{−0.25}) ≈ 0.64；相差 400 分时，P ≈ 0.91。

  • 优点：真实世界的 prompt（免费使用，用户有动力真正使用它）；不需要每个模型回答同样的 prompt（因为是人在打分，这很重要）；动态的，不断纳入新 prompt 和新模型。
  • 问题：这些人是谁？有偏见吗？有刷票的吗？二元偏好混淆了风格与正确性；人怎么判断正确性？容易被谄媚打动吗？

AlpacaEval（2023）

805 条来自各种来源的指令。指标：以 GPT-4 preview 为评审，相对基线模型（GPT-4 preview）的胜率。这有潜在偏见（评审偏爱自己）。更大的问题：LLM 评审偏爱更长的回答，导致排行榜被刷。AlpacaEval 2.0 用回归去除长度偏差。怎么评估这个指标本身？看它与 Chatbot Arena（人类判断）的相关性，相关性很高。

WildBench

从 100 万条真实人机对话中选出 1024 个例子。用 GPT-4 Turbo 带检查清单评审（类似评审时的思维链）。与 Chatbot Arena 相关性很好（这似乎已成为事实上的合理性检验）。

小结：难点是怎样评估开放式回答；在相似的回答之间做两两比较，信号更强；要当心偏见（人和 LLM 评审都有）；检查清单或评分细则能提高可靠性，无论评审是人还是 LLM。

05智能体类基准

之前评测的是 LM 说什么（对话），现在评测 LM 做什么（智能体）。智能体 = 语言模型 + 智能体框架（决定如何使用 LM 的逻辑）。考虑需要使用工具（如运行代码）并在一段时间内反复迭代的任务。

基准任务评测方式
SWE-Bench12 个 Python 仓库中的 2294 个任务：给定代码库和 issue 描述，提交 PR单元测试
Terminal-Bench计算机终端环境（简单且通用）；93 位贡献者众包的 229 个任务，其中 89 个构成 2.0 版按人类完成所需时间分析难度
CyBench40 个夺旗赛（CTF）任务用人类首次解出的时间衡量难度
MLE-Bench75 个 Kaggle 竞赛（需要训练模型、处理数据等）对照 Kaggle 排行榜的奖牌线

智能体框架

  • 显式规划：维护一个待办清单，逐项勾掉；
  • 分层委派：智能体调用子智能体（每个子智能体有干净的上下文）；
  • 持久记忆：读写文件；
  • 极致的上下文工程：给出更多关于流程的明确指令。

小结：智能体极大地扩展了语言模型的能力范围；框架非常重要；评测智能体 = 评测框架 + 语言模型，两者要分开报告。

06纯推理基准：ARC-AGI

前面所有任务都需要语言和世界知识。能不能把推理和知识分离开？可以说，推理体现了更纯粹的智能形式（不只是记住事实）。

ARC-AGI：人类能 100% 解出，对 AI 很有挑战。每个任务都是独特的，记忆没有用。

  • ARC-AGI-1（2019）：网格图案变换，从几个示例中归纳规则。
  • ARC-AGI-2（2025 年 3 月）：更多多步推理。
  • ARC-AGI-3（2026 年 3 月）：交互式环境。

预训练语言模型在这上面几乎没有进展；推理模型（o1、o3）出现后分数才开始起飞。

小结：目标是把推理和知识分开（很难做到）；局限于人类水平的推理（不是超人推理）；清楚地暴露了当前模型的差距。

07安全基准

汽车有碰撞测试评级。AI 的安全意味着什么？

  • HarmBench：基于 510 种违反法律或规范的有害行为。
  • AIR-Bench：基于监管框架和公司政策，分为 314 个风险类别、5694 个 prompt。

越狱

语言模型被训练成拒绝有害指令。GCG（贪心坐标梯度）自动优化出能绕过安全训练的 prompt 后缀，而且能从开放权重模型（Llama）迁移到闭源模型（GPT-4）。

安全是什么？许多方面强烈依赖语境（政治、法律、社会规范，各国不同）；风险类型非常多样（幻觉、谄媚、协助犯罪、不平等、丧失批判性思维）。还有两用性：能力强的网络安全智能体既能用来入侵系统，也能用来做渗透测试。

08现实性

生态效度：评测在多大程度上反映真实使用？考试类基准（如 GPQA）离真实使用很远；Chatbot Arena 的 prompt 来自真人，但分布不受控制。

  • GDPVal（OpenAI）：按美国 GDP 排名前 9 的行业中的 44 种职业，任务来自平均约 14 年经验的从业者。
  • MedHELM：以往的医学基准基于标准化考试；MedHELM 从 29 位临床医生那里收集了 121 个临床任务，混合私有和公开数据集。
  • Clio（Anthropic）：用语言模型分析真实用户数据，只公开人们在问什么的总体模式。

遗憾的是，现实性和隐私有时是矛盾的。

09有效性

训练—测试重叠

机器学习第一课：不要在测试集上训练。在基础模型之前（ImageNet、SQuAD）有明确的训练/测试划分；今天大家在整个互联网上训练，而且不告诉别人用了什么数据。

  1. 从模型推断重叠：利用数据点的可交换性。如果模型对基准原始顺序的似然明显高于随机打乱后的顺序，说明它见过这个基准。
  2. 鼓励报告规范：模型提供方应报告训练—测试重叠（就像大家报告置信区间一样）。
  3. 使用新鲜的评测：LiveCodeBench、UncheatableEval 抓取新网页。但时间戳也不绝对安全，因为内容会被复制。
  4. 使用私有评测：公司用不在互联网上的内部代码库；用你自己的写作。对困惑度来说最容易。

数据集质量

  • 修正 SWE-Bench 得到 SWE-Bench Verified（人工筛掉描述不清或测试有问题的任务）。
  • 为基准制作“白金版”：修正标错的题目，剩下的错误才真正反映模型的问题。
  • 智能体基准的问题：测试用例不够充分，一个什么都不做的智能体就能通过部分任务。
  • Docent：用 LLM 检查智能体的执行轨迹，发现问题。

10怎样思考评测

评测的目的是什么？取决于你要回答的问题：

  1. 用户或公司要做采购决策（模型 A 还是 B），针对自己的场景（例如客服机器人）；
  2. 研究者想测量模型的原始能力（例如智能）；
  3. 我们想了解模型的收益与危害（出于商业和政策原因）；
  4. 模型开发者想得到反馈来改进模型。

我们在评测什么？基础模型之前，评测的是方法（标准化的训练/测试划分）；今天大多评测的是模型或系统（怎样都行）。也有例外：nanoGPT speedrun 固定数据，比较达到某个验证 loss 所需的时间。评测方法鼓励研究者做算法创新；评测模型或系统对下游用户有用。无论哪种，都要把游戏规则说清楚。

11本课要点

  • 没有唯一正确的评测，要根据你想测量的东西来选。
  • 说清楚游戏规则：评测的是方法、模型，还是智能体（框架 + 模型）。
  • 三个考量：难度、现实性、有效性。
  • 困惑度平滑、便宜，适合开发；考试、对话、智能体、推理、安全基准各自覆盖能力的不同侧面。
  • LLM 评审有长度等偏见，检查清单和去偏回归能提高可靠性；数据污染要通过推断、报告、新鲜或私有评测来应对。

12自测题

Q1一个模型在测试集上的平均交叉熵是 2.3 nats/token，困惑度是多少？

e^{2.3} ≈ 10。平均相当于在 10 个等可能的 token 中选择。

Q2两个用不同 tokenizer 的模型，困惑度能直接比较吗？该怎么比？

不能，每个 token 覆盖的文本量不同。可以换成与分词无关的单位，例如每字节比特数（bits per byte）：总负对数似然除以文本的 UTF-8 字节数。

Q3模型 A 的 Elo 比 B 高 200 分，A 的预期胜率是多少？

1 / (1 + 10^{−200/400}) = 1 / (1 + 10^{−0.5}) ≈ 1 / 1.316 ≈ 0.76。

Q4为什么 AlpacaEval 需要做长度去偏？

LLM 评审倾向于认为更长的回答更好，与质量无关。模型只要回答得更长就能涨分，排行榜会被刷。用回归控制长度后，胜率才更接近真正的质量差异，与人类偏好的相关性也更高。

Q5怎样用“可交换性”检测一个模型是否在某个基准上训练过？

如果基准的样本顺序本身没有意义（可交换），一个没见过它的模型对原始顺序和随机打乱顺序应给出相同分布的似然。如果模型对原始顺序的似然显著高于大量随机顺序，就说明它很可能记住了这个基准文件。
