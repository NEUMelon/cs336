01从第一性原理出发

第一性原理

把一个模型放大，需要设定三类东西：

  1. 架构超参数（宽度、深度等）；
  2. 优化超参数（学习率、批大小）；
  3. 模型大小与数据量的分配（Chinchilla 式分析）。

对每一类，都有两种策略：要么让它不随规模变化（通过合适的参数化，比如 muP，让小模型上调好的学习率直接适用于大模型），要么显式拟合它随规模变化的规律（在小规模上找最优值，拟合幂律，再外推）。

还有一个纯粹的成本问题：Chinchilla 分析要求每个（模型大小，数据量）组合都从头训练到结束，成本是平方级的。能不能让一次训练同时提供多个数据量下的结果？这就是 WSD 学习率调度的意义。

今天的问题：Chinchilla 的缩放方法在实践中到底管不管用？训练和拟合时能否节省算力？是否应该选择特定的架构或参数化，使模型能良好地缩放？初始化、优化器以及学习率/批大小等超参数都可能对规模敏感。

02案例一：MiniCPM

MiniCPM（2024，清华团队）是一系列 1–2.5B 参数的小模型，性能超过大多数 2B 模型，追平许多 7B 模型。它算不上当时的最强模型，但在缩放上做了细致而大量的计算，并用 muP 让缩放更稳定、更简单，有很多值得学习的地方。

技巧一：用 muP 稳定缩放

具体超参数：scale_emb = 12，scale_depth = 1.4，init_std = 0.1，lr = 0.01。策略是：用 muP 初始化，固定宽高比，整体放大模型。注意用来拟合的最大模型和最终训练的模型之间差了约 5 倍。最优批大小、学习率、tokens/参数比都直接通过缩放分析拟合出来。

  • 最优学习率：按 muP 的说法，最优学习率应该大致不随规模变化。实测确实大致稳定。
  • 最优批大小：在 9M、30M、170M 三种模型上，把数据量、批大小和 loss 画在一起；每个数据量下 loss 最低的批大小就是最优批大小。再照 Kaplan 2020 的方法画出最优批大小与最终 loss 的关系：趋势很干净，loss 越低，批大小按多项式增大。

技巧二：WSD 学习率让 Chinchilla 分析变便宜

问题：Chinchilla 分析要从头训练，不能只是提前停止（cosine 调度的中间点不是那个数据量下的最优结果）。拟合 scaling law 的成本从 n 变成 n²。

WSD（warmup–stable–decay）：把学习率分成三段：预热、恒定、衰减（衰减段约占 10%）。

关键：稳定段的学习率是常数，与总训练长度无关。所以只需跑一条长的稳定段，在不同的数据量处“分叉”出去单独做衰减，就能得到这些数据量下各自的最终 loss。

成本：一条主干 + 若干短衰减段，大约从 n² 降到 n。

WSD 在 MiniCPM 中效果很好：稳定段 loss 下降较慢，衰减段 loss 快速下降。

Chinchilla 式分析

有了 WSD，就可以寻找最优的数据/模型比。MiniCPM 用了方法 1（下包络）和方法 3（联合拟合）。方法 1 的趋势相当清晰（虽然也许不是线性的），显示数据带来的收益递减较弱。主要依据方法 3，他们得到了非常高的数据/模型比。

03案例二：DeepSeek LLM

DeepSeek（2024）是另一个做了细致缩放分析的模型，7B 和 67B 两个版本的性能在当时的开放模型中都很高。

批大小和学习率：直接拟合

策略：不用 muP，直接估计最优批大小和学习率随规模的变化。在小规模上训练，收集所有“接近最优”（loss 在最小值 0.25% 以内）的配置，然后对算力 C 拟合幂律。论文给出的拟合约为 B_opt ∝ C^0.33、η_opt ∝ C^−0.125：算力越大，批越大，学习率越小。学习率的拟合看起来有点可疑，数据点很分散。

分段学习率

DeepSeek 也用类似 WSD 的调度：快速预热，然后两个各占约 10% 训练量的阶梯式衰减。效果与 cosine 大体相当，而且同样能复用前面的训练。

模型大小：IsoFLOP

用 Chinchilla 方法 2（IsoFLOP）来确定模型大小。拟合出的 scaling law 能相当准确地预测最终模型的 loss（7B 和 67B 都落在预测线上）。

05学习率和批大小该怎么随规模变化

StepFun 做了一项大规模的 scaling law 研究，核心问题正是 DeepSeek/Qwen 的方法：放大时怎样设置学习率和批大小？该用什么变量和函数形式？

  • OpenAI 的观点：临界批大小是 loss 的函数；
  • DeepSeek 的观点：是算力的多项式函数；
  • ……或者别的形式。

方法是纯经验的：像 DeepSeek 一样做网格搜索，把超参数空间整个画出来。

  1. 观察一：预训练 loss 关于学习率和批大小是凸的，最小值可以清楚地找到。
  2. 观察二：在 Chinchilla 式的联合缩放中，最优批大小主要取决于数据量 D。他们还发现固定模型大小时，D 越大最优学习率越高；但换成 WSD 调度后这个结论可能不那么稳健（见 InternLM 的 scaling law 论文，Zhou et al., 2026）。
  3. 观察三：这些规律对 MoE 和其他数据集也大致成立。

06优化器与规模

优化是 LLM 的核心部分，但也很棘手，因为它依赖规模。

  • 问题一：超参数常常没调好。不同优化器需要不同的超参数，最优超参数随规模的变化也可能不同。比较优化器时，如果只给一方认真调参，结论就不可信。
  • 问题二：强烈的规模依赖。做算法研究时，一定要检查它在不同算力和不同 tokens/参数比下的表现。这两者常常是性能的主要混杂因素：一个在 1× Chinchilla 下领先的优化器，在 8× 下可能优势消失。
  • 问题 2.5：建立 scaling 本身就不容易。一条看起来很好的缩放曲线也可能在更大规模时突然崩溃。例如 Marin 的 Delphi 实验：Cautious AdamC 加上按批大小平方根缩放学习率，在放大时出了问题，后来通过更仔细的参数化、缩放规则和优化器修改才解决。

Muon

Muon 是专门为矩阵形参数设计的优化器：先像 SGD 一样算动量 B_t，再用 Newton–Schulz 迭代把它（近似）正交化：

B_t = U S Vᵀ → U Vᵀ保留奇异向量，把所有奇异值变成 1
补充：为什么要正交化

梯度矩阵往往是“病态”的：少数几个奇异方向的奇异值特别大，更新几乎全挤在这些方向上。把奇异值全部拉平为 1，相当于让更新在所有方向上走一样大的一步，对应在谱范数约束下的最速下降。Newton–Schulz 只用矩阵乘法迭代几次，不需要真正做 SVD，在 GPU 上很便宜。嵌入层、输出层和标量参数仍用 AdamW。

证据：NanoGPT speedrun（规模很小）里 Muon 明显更快；专门的缩放研究；Kimi K2 用 Muon（MuonClip）训练了万亿参数的 MoE。缩放收益很难精确衡量，但 Muon 显然在大规模上是“管用”的。

07muP 深入

最大更新参数化（muP）宣称：超参数调优可以与规模无关。这非常诱人。它是怎么做到的？实践中真的成立吗？CerebrasGPT（0.1B 到 13B，按 Chinchilla 配方训练）发现使用 muP 参数化让缩放更稳定。

muP 的两个断言

第一性原理

设第 l 层的宽度为 n_l。当宽度变化时：

  • A1：初始化时，每个激活值的大小应该是 Θ(1)；
  • A2：走一步梯度之后，每个激活值的变化量也应该是 Θ(1)。

如果单个激活是 Θ(1)，那么整个激活向量的范数是 Θ(√n_l)。A1 保证前向信号不爆炸也不消失；A2 保证每一层都在“学习”，既不太快（发散）也不太慢（冻结）。满足这两条，最优学习率就不随宽度变化。

推导 A1：初始化

考虑深层线性网络 h_l = W_l h_{l−1}，初始化 W_l ~ N(0, σ²)，形状 n_l × n_{l−1}。由矩阵集中不等式，谱范数

‖W_l‖* → σ (√n_{l−1} + √n_l)，并且 ‖h_l‖₂ ≈ ‖W_l‖* ‖h_{l−1}‖₂

（这是“最坏情况”的推导，≈ 实际上是上界。）取

σ = √(n_l / n_{l−1}) · (√n_l + √n_{l−1})^{−1} = Θ( (1/√n_{l−1}) · min(1, √(n_l/n_{l−1})) )

归纳：若 ‖h_{l−1}‖₂ = Θ(√n_{l−1})，则 ‖W_l‖* = √(n_l/n_{l−1})，于是 ‖h_l‖₂ = √n_l + o(√n_l)。A1 成立。

推导 A2：学习率

SGD 下线性层的更新是一个秩一外积：ΔW_l = −η_l ∇_{h_l}ℓ · h_{l−1}ᵀ，所以 ‖ΔW_l h_{l−1}‖₂ = ‖ΔW_l‖* ‖h_{l−1}‖₂。

激活的变化：Δh_l = W_l Δh_{l−1} + ΔW_l (h_{l−1} + Δh_{l−1})。假设主导项不相互抵消：

  • W_l Δh_{l−1} = Θ(√n_l)（归纳假设 + A1 的论证）；
  • ΔW_l h_{l−1} = ‖ΔW_l‖* · √n_{l−1}。要它也是 Θ(√n_l)，需要 ‖ΔW_l‖* = Θ(√(n_l/n_{l−1}))；
  • ΔW_l Δh_{l−1} 是更高阶的小量。

接下来选学习率使 ΔW 恰好是这个大小。假设 loss 的变化量也是 Θ(1)：

Δℓ ≈ ⟨ΔW_l, ∇_{W_l}ℓ⟩ = Θ(‖ΔW_l‖_F ‖∇_{W_l}ℓ‖_F) = Θ(‖ΔW_l‖* ‖∇_{W_l}ℓ‖*)

（秩一矩阵的 Frobenius 范数等于谱范数。）代入 Δℓ = Θ(1) 和 ‖ΔW_l‖* = Θ(√(n_l/n_{l−1}))，得 ‖∇_{W_l}ℓ‖* = Θ(√(n_{l−1}/n_l))。由 ΔW_l = −η_l ∇_{W_l}ℓ：

η_l = ‖ΔW_l‖* / ‖∇_{W_l}ℓ‖* = Θ(n_l / n_{l−1})

Adam 的更新经过逐元素归一化，每个元素大小约为 η，秩一更新的谱范数约为 η √(n_l n_{l−1})；令它等于 √(n_l/n_{l−1})，得 η_l = Θ(1/n_{l−1})，即按输入宽度（fan-in）的倒数缩放。

小结：muP 与标准参数化

muP标准参数化（SP）
初始化标准差Θ( (1/√n_{l−1}) · min(1, √(n_l/n_{l−1})) )1/√n_{l−1}
学习率（SGD）n_l / n_{l−1}Θ(1)
学习率（Adam）1 / n_{l−1}Θ(1)

差别在于：Adam 的学习率要随宽度缩放；输出宽度小于输入宽度（fan-out < fan-in）时初始化也不同。完整的 muP 还为不同类型的参数分别规定了规则：注意力参数（注意力 logits 按 1/d 而不是 1/√d 缩放）、嵌入层、MLP 的输入输出矩阵、输出 softmax 的线性层。

muP 真的管用吗

问题一：放大宽度时，最优学习率真的保持不变吗？复现实验显示，在标准设定下基本成立。

现代 LM 有很多偏离 muP 理论的组件：SwiGLU 和 squared ReLU 激活、大/小批大小、各种初始化变体（例如零初始化注意力）、RMSNorm 的增益参数、特殊优化器（Lion）、正则化。哪些会破坏 muP？

因素muP 是否仍然成立
SwiGLU、squared ReLU、批大小变化、初始化变体基本成立
RMSNorm 的可学习增益不成立，但去掉这些增益几乎不损失性能
只用梯度符号的特殊优化器（如 Lion）不成立
强 weight decay（0.1）不成立，这可能是唯一显著的失败

总体而言，muP 看起来是有用的：标准参数化明显更不稳定。现有证据表明，muP 的参数化和初始化可能更容易调。

08本课要点

实践中的挑战可能的解决方案
设置架构超参数（宽度等）假设它们不随规模变化（或用 muP 保证）
设置优化器超参数（学习率、批大小）在小规模上搜索最优值，要么保持固定，要么拟合规律来预测
拟合大规模 Chinchilla 扫描所需的算力使用 WSD 之类的学习率调度，复用训练
  • 公开配方分两派：DeepSeek 直接拟合学习率/批大小的幂律；MiniCPM 用 muP 让它们与规模无关。
  • 最优批大小主要取决于数据量（或目标 loss），随之增大；学习率随规模减小。
  • 比较优化器时，一定要在多个算力和多个 tokens/参数比下比较。
  • muP 由“激活及其变化都是 Θ(1)”两条原则推出；对 Adam，学习率按 1/fan-in 缩放。

09自测题

Q1WSD 为什么能把 Chinchilla 分析的成本从 n² 降到约 n？cosine 为什么不行？

cosine 调度的形状依赖总步数，训练中途的检查点并不是“以这个数据量为目标训练”的结果，每个数据量都要单独从头跑。WSD 的稳定段学习率与总长度无关，可以从同一条主干的不同位置分叉，只需补一段短的衰减，就得到各个数据量下的最终 loss。

Q2用 Adam 训练，基础模型宽度 256、学习率 1e-2 调到最优。按 muP，把隐藏层宽度放大到 4096，隐藏层的学习率应该设为多少？

Adam 下 η ∝ 1/fan-in，宽度放大 16 倍，学习率缩小 16 倍：1e-2 / 16 ≈ 6.25e-4。

Q3为什么 muP 要求“激活的变化量”是 Θ(1)，而不只是激活本身？

只控制初始化只能保证前向信号大小正常。如果更新量随宽度变大，宽模型会在一步之内把激活改得面目全非（发散）；如果随宽度变小，宽模型几乎不学习（进入“lazy”/核区间）。只有更新量也是 Θ(1)，每一层才会以与宽度无关的速度学习特征，最优学习率才能跨宽度迁移。

Q4Muon 对矩阵 B = USVᵀ 做了什么？为什么这可能比 Adam 的逐元素归一化更好？

把它换成 UVᵀ，即保留方向、把所有奇异值设为 1。Adam 逐元素地归一化，不考虑矩阵结构；Muon 在矩阵层面均衡了各个奇异方向上的步长，防止更新集中在少数几个主方向上，对应谱范数意义下的最速下降。

Q5Llama 3 的 IsoFLOP 得到 39:1，Hunyuan 得到 96:1（对激活参数），都远大于 Chinchilla 的 20:1。可能的原因有哪些？

数据质量和数据处理不同（更好的数据改变 scaling law 的系数）；架构与优化改进；MoE 的“参数”定义不同（激活参数 vs 总参数）；拟合方法和规模范围不同。最优比例不是普适常数，要在自己的设置下重新拟合。
