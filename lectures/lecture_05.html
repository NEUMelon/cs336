GPU：执行模型、内存层级与 FlashAttention

语言模型的进步离不开算力的扩展，而今天的算力扩展几乎全靠 GPU 的并行。这一课拆开 GPU：它怎么组织线程、内存为什么分层、什么时候会变慢；然后用六个技巧（控制分歧、低精度、算子融合、重计算、合并访存、分块）解释怎么让它变快，最后用这些知识读懂 FlashAttention。

01从第一性原理出发

第一性原理

事实一：算力增长快于内存带宽。过去 20 年，硬件峰值 FLOP/s 的增长远超 DRAM 带宽和互连带宽的增长（所谓“内存墙”）。所以绝大多数时候，计算单元在等数据。

事实二：离计算越近的内存越快，也越小越贵。寄存器 → 共享内存/L1（在 SM 内部）→ L2（在芯片上）→ HBM（芯片旁边的显存）。SRAM 比 DRAM 贵约 100 倍，快约一个数量级。

推论：性能优化的核心就是减少对慢速内存的访问次数：把数据搬进快速内存后尽可能多地复用（分块），把多个操作合并成一次读写（融合），用更少的位表示数据（低精度），宁可重算也不存取（重计算），并且按硬件喜欢的方式成块读取（合并访存）。

本课目标：让 CUDA 和 GPU 不再神秘；理解 GPU 什么时候会变慢；理解如何设计快速算法。致谢：Horace He 的博客、CUDA MODE 社区、Google 的 How to Scale Your Model。

背景：算力能带来可预测的性能提升（scaling laws）。早期靠 Dennard 缩放（单核越来越快），到 2000 年代这条路走到了尽头；此后靠并行扩展，GPU 的算力 10 年增长了 1000 倍以上。没有 GPU 的扩展，就没有 LLM 的扩展。

02GPU 的结构

GPU 和 CPU 的区别

CPUGPU
优化目标延迟：让每个线程尽快完成吞吐：总共处理尽可能多的数据
线程少量快速线程海量线程
芯片面积花在控制逻辑、分支预测、大缓存大量小计算单元（ALU）

执行单元

GPU 由许多 SM（streaming multiprocessor）组成，每个 SM 独立执行“块”（block）；每个 SM 里又有许多 SP（streaming processor），可以并行执行线程。H100 SXM 有 132 个 SM。

内存层级

层级位置H100 容量（约）谁能访问
寄存器SM 内每 SM 256 KB单个线程
共享内存 / L1SM 内每 SM 最多约 228 KB同一个 block 内的线程
L2 缓存芯片上50 MB所有 SM
全局内存（HBM）芯片旁80 GB，约 3.35 TB/s所有 SM，最慢

执行模型：线程、块、warp

  • 线程（thread）：真正干活的单位。所有线程执行相同的指令，只是输入不同（SIMT：单指令多线程）。
  • 块（block）：一组线程。每个块在一个 SM 上运行，有自己的共享内存。
  • Warp：线程总是以 32 个连续编号的线程为一组（warp）一起执行。

内存模型：每个线程能访问自己的寄存器和本块的共享内存。跨块的信息必须经过全局内存（慢）。这条限制决定了很多 kernel 的设计。

TPU 呢？

GPU、TPU 和其他加速器在高层上很像：轻量的控制逻辑 + 快速的大矩阵乘单元 + 快速内存。差别在于：TPU 没有 warp，只有块（在矩阵乘法与非矩阵运算之间有不同的取舍）；GPU 的 SM 多，TPU 的 TensorCore 少但每个更大，总的矩阵乘性能相近；两者的组网方式不同（并行那一课再讲）。

GPU 就是快速矩阵乘法器

早期研究者用可编程着色器“骗” GPU 做矩阵乘法。V100 起引入了 Tensor Core，专门做矩阵乘法的电路。现在矩阵乘法比其他浮点运算快 10 倍以上。所以一个设计如果不能写成矩阵乘法，在 GPU 上就会吃亏。

GPU 模型的优点：加 SM 就能扩展；SIMT 模型相对好编程；线程轻量，可以随时挂起和切换（某个 warp 等内存时，SM 切换到另一个 warp，这就是隐藏延迟的方式）。

03让 GPU 变快的六个技巧

即使是方阵乘法，性能表现也可能很复杂。回忆 roofline 模型：这一部分的关键问题是怎样避免 memory-bound。

技巧 0：避免控制分歧

这不是内存问题。一个 warp 内的所有线程在同一时刻执行同一条指令。如果 warp 内有 if/else 分支，两条路径会串行执行：走 if 的线程执行时，走 else 的线程闲着，反之亦然。条件分支可以用，但开销显著。

技巧 1：低精度计算

位数少了，要搬的字节就少了。以 n 个元素的逐元素 ReLU 为例：

精度访存运算每次运算需要的字节
fp32读 x、写 x，各 4 字节1 次比较8
fp16读 x、写 x，各 2 字节1 次比较4

精度减半，算术强度翻倍。另外 Tensor Core 在低精度下吞吐更高（例如 fp16/bf16 输入、fp32 累加）。

低精度的前沿：块缩放格式。

  • MXFP8（Blackwell 支持）：元素用 E4M3（因为有了更多缩放因子，可以多给尾数），每 32 个元素共享一个 E8M0 缩放因子（只有指数，就是一个 2 的幂）。代价是转置变得不再简单：沿行分块和沿列分块的缩放因子不同，转置后要重新量化。实际训练中并非所有权重都用 MXFP8。
  • FP4：每个值只有 15 种取值。讲义这一页标题写的是 MXFP4，但给出的参数（每 16 个值一个 E4M3 缩放因子）对应的是 NVIDIA 的 NVFP4；标准 MXFP4 是每 32 个值一个 E8M0 缩放因子。

技巧 2：算子融合

把 GPU 想成一座工厂：原料从仓库（内存）运来，在工厂（计算单元）加工。工厂在不断扩建，但运输道路没有同步加宽。如果要做多道工序，每道工序都把半成品运回仓库再运回来，就太傻了。

例：sin²x + cos²x，朴素执行要启动 5 个 kernel（sin、cos、两次平方、加法），每个都读写一遍 HBM：约 5 次读、5 次写。

融合成一个 kernel：读一次 x，在寄存器里算完全部 5 步，写一次结果。访存降为 2 次（每元素）。

这种“简单”融合（逐元素操作串起来）编译器可以自动完成，例如 torch.compile。

技巧 3：重计算

反向传播要用前向存下的激活值。存和取激活值本身就很贵。

例：三个 sigmoid 叠在一起。朴素做法：前向读 x、写 3 个中间激活；反向再读这些激活，总共 8 次内存读写，算术强度极低。

重计算：前向只读 x、写输出；反向时从 x 重新算出中间值（它们只在寄存器里存在），总共 5 次内存访问，是原来的 5/8。

和第二课的激活检查点是同一个思想：当瓶颈是内存访问时，丢掉计算结果、需要时重算，反而更快。

技巧 4：合并访存

DRAM 以突发模式（burst mode）读取：一次读操作会返回一整段连续的字节。原因在硬件：把 DRAM 的一行复制到感测放大器很慢，而一旦复制完，读这一行中的相邻字节就很便宜。

如果一个 warp 的 32 个线程访问的地址落在同一个 burst 里，这些访问会被合并成一次。对行优先存储的矩阵：同一 warp 的线程如果沿着行的方向读（相邻线程读相邻列），就是合并的；如果每个线程读不同的行，就不合并，一个 warp 要发起很多次读取。

技巧 5：分块（最重要的一个）

分块就是对线程进行分组和排序，以最小化全局内存访问。回到矩阵乘法 P = M × N（都是 N×N）：朴素实现中，每个线程算 P 的一个元素，要读 M 的一整行和 N 的一整列。访存不合并，而且同样的数据被不同线程反复从全局内存读取。

按阶段计算：① 把 M₀,₀ 和 N₀,₀ 两个块载入共享内存；② 计算 P 这一块的部分和；③ 载入下一对块（M₀,₁ 和 N₁,₀）；④ 重复直到走完。

分块能省多少？朴素实现中，M 的每个元素要被 P 的同一行的 N 个线程各读一次：每个输入从全局内存读 N 次。

分块后，一个元素所在的块只需被载入一次就能供 T 个输出使用：每个输入从全局内存读 N/T 次，在共享内存里读 T 次。全局内存访问减少 T 倍，而且载入整块时访问是连续的，可以合并。

分块的复杂之处

  • 块大小不整除矩阵维度：边缘的块只有部分有效数据，SM 利用率下降（tile quantization）。
  • 影响块大小的因素：合并访存、共享内存容量、矩阵维度的可整除性。
  • 内存对齐：burst 按固定边界对齐。如果矩阵的行长度不是合适的倍数，块的起始地址就不对齐，一次载入跨越两个 burst，此时需要填充（padding）。

04矩阵乘法之谜：形状为什么影响速度

来自 Horace He 的博客 What shapes do matrix multiplications like?：画出方阵乘法的吞吐随尺寸变化的曲线，会看到三种现象。

  1. 整体上升：矩阵越大，算术强度越高（第二课：约 n/3），越接近 compute-bound。
  2. 对齐造成的分层：维度是 32、16、8、2 的倍数时速度依次下降，奇数维度最慢。这是分块和对齐的影响。
  3. 周期性的骤降：这是波量化（wave quantization）。

用 256 × 128 的块计算 1792 × 1792 的输出：(1792/256) × (1792/128) = 7 × 14 = 98 个块。A100 有 108 个 SM，一“波”就全部算完。

尺寸变成 1793：⌈1793/256⌉ × ⌈1793/128⌉ = 8 × 15 = 120 个块。108 个 SM 一波算不完，要第二波，而第二波只有 12 个块，大部分 SM 空转。

多了 1 行数据，耗时几乎翻倍：利用率从 98/108 ≈ 91% 掉到 120/216 ≈ 56%。

实用结论把模型维度、词表大小、batch 大小设成 64 或 128 的倍数，是便宜又有效的优化。Karpathy 把 nanoGPT 的词表从 50257 填充到 50304（64 的倍数）就获得了明显的提速。

小结：让 ML 负载变快

  • 减少内存访问：合并访存、融合。
  • 把数据搬到共享内存：分块。
  • 用内存换计算或精度：量化、重计算。

05读懂 FlashAttention

FlashAttention（Dao et al.）大幅加速了注意力。它没有减少 FLOPs，而是减少了 HBM 访问。

朴素注意力的问题

注意力是三次矩阵乘法中间夹一个 softmax：S = QKᵀ，P = softmax(S)，O = PV。朴素实现把 n×n 的 S 和 P 写回 HBM，再读回来。n 很大时，这两个矩阵的读写远远超过 Q、K、V 本身的大小，完全是 memory-bound。

第一步：对 QKᵀV 分块

FlashAttention 论文的图 1 就是对 QKᵀV 这串矩阵乘法做分块：把 Q 切成行块，K、V 切成列块，在 SRAM 里算出一块 S，马上乘上对应的 V 块并累加到输出上，n×n 矩阵永远不写回 HBM。难点在 softmax：它要对整行做归一化，而我们一次只看到一行的一部分。

第二步：在线 softmax

数值稳定的 softmax 要先减去最大值：softmax(x)ᵢ = e^{xᵢ−m} / Σⱼ e^{xⱼ−m}，m = max x。朴素做法需要三遍扫描：求 m、求分母、归一化。

在线版本（Milakov & Gimelshein, 2018）只扫一遍，维护两个量：当前最大值 m 和以当前最大值为基准的分母 d。每来一个新值 xⱼ：

m' = max(m, xⱼ)

d' = d · e^{m − m'} + e^{xⱼ − m'}

第一项把旧的分母从旧基准“换算”到新基准（伸缩求和），第二项加上新元素。最后 d 就是正确的分母。这里可以一次处理一整块，而不必一个元素一个元素地处理。

用到注意力上：输出 O 也按同样方式维护一个未归一化的累加器 o。处理新的一块 S 和 V 时：

o' = o · e^{m − m'} + Σⱼ e^{sⱼ − m'} vⱼ

所有块处理完后，O = o / d。

合在一起：前向传播

  • 逐块计算内积 S（分块）；
  • 指数运算直接融合在同一个 kernel 里（融合）；
  • 用在线、伸缩求和的方式逐块计算 softmax。

反向传播本课不展开：它不存 n×n 的 P，而是只存每行的 m 和 d（O(n) 大小），反向时逐块重计算 S 和 P。这里分块、融合、重计算三种技巧都用上了。

补充：HBM 访问量

标准注意力的 HBM 访问量为 Θ(nd + n²)。FlashAttention 为 Θ(n²d²/M)，其中 M 是 SRAM 大小。典型情况下 d = 64–128，M 约 100 KB，d²/M 远小于 1，访存大幅减少。FLOPs 反而因为重计算略有增加，但整体快了好几倍。

06本课要点

  • 硬件能力在扩展，但底层细节决定了什么能扩展、什么不能。
  • GPU 是大规模并行的 SIMT 机器：线程 → warp（32 个）→ 块（一个 SM）。跨块通信只能走全局内存。
  • 算力（尤其是 Tensor Core 矩阵乘法）比内存扩展得快，所以要以“矩阵乘法 + 数据搬运”为中心思考。
  • 六个技巧：避免控制分歧、低精度、融合、重计算、合并访存、分块。
  • 形状很重要：对齐和波量化能让多 1 行数据的矩阵乘法慢近一倍。
  • FlashAttention = 分块 + 融合 + 在线 softmax + 反向重计算。

07自测题

Q1一个 warp 里一半线程走 if、一半走 else，吞吐会怎样？

两条路径串行执行，每条路径执行时只有一半线程在工作，这段代码的有效吞吐约减半。

Q2分块大小 T 越大越好吗？受什么限制？

全局内存访问减少 T 倍，所以希望 T 大。但两块 T×T 数据（及输出累加器）要放进共享内存和寄存器；T 太大会让每个 SM 能同时运行的块变少（occupancy 下降），也会加重边缘块浪费和波量化。

Q3在 H100（132 个 SM）上用 128 × 128 的块算 2048 × 2048 的输出，一共几波？最后一波利用率多少？

块数 16 × 16 = 256。第一波 132，第二波 124，共 2 波。第二波利用率 124/132 ≈ 94%，整体 256/264 ≈ 97%。

Q4用在线 softmax 处理序列 [1, 3, 2]，写出每步的 m 和 d。

初始 m = −∞，d = 0。x=1：m=1，d = 0 + e⁰ = 1。x=3：m=3，d = 1·e^{1−3} + e⁰ = e⁻² + 1 ≈ 1.135。x=2：m=3，d = 1.135 + e^{−1} ≈ 1.503。验证：e^{−2} + e⁰ + e^{−1} ≈ 0.135 + 1 + 0.368 = 1.503。

Q5FlashAttention 的 FLOPs 比标准注意力多还是少？为什么还是更快？

略多（反向要重算 S 和 P）。但标准注意力是 memory-bound 的，时间花在读写 n×n 矩阵上；FlashAttention 让这些矩阵只存在于 SRAM，HBM 访问大幅下降，所以更快。又一次说明 FLOPs 不等于运行时间。

Q6为什么 sin²x + cos²x 融合后能快好几倍，而一个大矩阵乘法融合一个 ReLU 只快一点点？

前者全是 memory-bound 的逐元素操作，时间基本等于访存次数，5 次读写降到 1 次，就快了约 5 倍。后者的主体矩阵乘法是 compute-bound 的，ReLU 省下的一次读写只占总时间的很小一部分。
