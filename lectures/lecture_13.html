01从第一性原理出发

第一性原理

预训练的目标是最小化训练数据上的交叉熵，所以模型学到的就是训练数据的分布。模型会写什么代码、懂几种语言、有什么知识，都取决于数据里有什么、各占多少。架构和系统决定学得多快、多省，数据决定学到的是什么。

数据的根本特点：

  • 数据不会从天上掉下来：从在线服务 → 原始数据 → 处理后的数据（转换、过滤、去重），每一步都需要工作和取舍。
  • 数据是长尾问题：与架构和系统不同，它随人力投入而扩展，很难用一个优雅的方法一劳永逸地解决。
  • 质量与数量的权衡：训练过程从大量的低质量数据逐步走向少量的高质量数据。

02为什么数据最重要

数据是训练语言模型时最需要做对的东西。一个佐证：看看公司都披露了什么。开放权重模型（例如 Llama 3）对架构完全透明，甚至公开了训练流程，但对数据几乎只字不提。保密的原因：① 竞争；② 版权责任。

在基础模型之前，数据工作意味着为监督学习做大量人工标注。现在标注少了，但仍有大量的整理和清洗工作。

训练的阶段

阶段数据OLMo 2 的例子
预训练原始文本（如网页文档），数量巨大OLMo-Mix（DCLM 网页 + 代码 + 论文 + 数学等，数万亿 token）
中期训练更高质量的数据，用来增强能力Dolmino（高质量网页、数学、合成数据等）
后训练对话记录，或强化学习Tülu 3（SFT、偏好数据、可验证奖励的 RL）

实际中界限很模糊，也可能有更多阶段，但基本趋势是从大量低质量数据走向少量高质量数据。术语：基础模型是预训练 + 中期训练之后的模型；指令/对话模型是后训练之后的模型。越来越多的公司不再发布基础模型（例如 Qwen3.5-397B-A17B 只发布了指令模型）。

03原始来源：“整个互联网”？

常听人说“语言模型是在整个互联网上训练的”。更准确地说是公开的万维网，但这也不完全对。

首先，网络是一组可以连接的在线服务器（curl https://cs336.stanford.edu/），你不能在在线服务器上训练。爬虫从种子集合出发发现网页，并下载发现的网页。但你也没法下载所有网页：

  • 动态内容：很多网站其实是应用，URL 不变，需要点按钮、提交表单才能看到内容（例如 Discord、wandb）。
  • 身份认证：需要登录（通常还要付费），例如 Facebook、X、LinkedIn、纽约时报，大量内容在围墙花园里。
  • 技术限制：robots.txt 禁止下载某些内容（自愿遵守）；Cloudflare 识别并拦截机器人（弹出验证码）；封锁某些 IP 或国家；限流。
  • 法律限制：服务条款可能禁止用机器人下载；你可能没有复制网页（用于训练）的许可。

许可的衰退（Longpre et al., 2024）：检查常见数据集（C4、RefinedWeb、Dolma）中 URL 的限制（robots.txt、服务条款），发现限制随时间越来越多。爬虫不守规矩时，网站会付出代价：服务变慢、流量费用增加。

影子图书馆：Library Genesis、Z-Library、Anna's Archive、Sci-Hub 技术上也是网络的一部分。它们无视版权、绕过付费墙（如 Elsevier），收到过下架令和诉讼，在许多国家被封锁，通常把服务器放在多个国家来规避管控。有人认为这让本应免费的知识变得免费；从法律角度看，这是盗版和侵犯版权。LibGen 约有 400 万本书（2019），Sci-Hub 约有 8800 万篇论文（2022）。

04版权：哪些数据能合法使用

知识产权法

目标是激励智力成果的创作。类型包括版权、专利、商标、商业秘密。

  • 版权法可追溯到 1709 年英国的《安妮法令》，第一次由政府和法院管理。美国现行的是 1976 年《版权法》。
  • 保护对象：“固定在任何有形表达媒介上的原创作品”。
  • 汇编不是原创作品，因此不受版权保护（如电话簿），除非在选择或编排上有创造性。
  • 版权保护的是表达，不是思想（例如快速排序算法本身不受保护）。
  • 保护范围从“已出版”（1909）扩展到“已固定”（1976）；不需要登记就受保护（与专利不同）；门槛极低（你的个人网站就有版权）。
  • 起诉侵权之前必须先登记（费用 65 美元）。保护期结束后作品进入公有领域（莎士比亚、贝多芬、古腾堡计划的大部分书）。
结论互联网上基本上一切内容都有版权。要使用受版权保护的作品，只有两条路：① 获得许可；② 援引合理使用。

许可

许可（来自合同法）由许可方授予被许可方。实际上，“许可就是一个不起诉的承诺”。知识共享（Creative Commons）许可允许自由传播受版权保护的作品：维基百科、开放课件、可汗学院、Flickr 的 3 亿张图片等。它由 Lessig 和 Eldred 于 2001 年创立，用来连接公有领域和现有版权。许多模型开发者会购买训练数据的许可：Google 与 Reddit、OpenAI 与 Shutterstock、OpenAI 与 StackExchange。

合理使用（第 107 条）

因素更倾向于合理使用
1. 使用的目的和性质教育优于商业；转化性优于复制性
2. 作品的性质事实性优于虚构；非创作性优于创作性
3. 使用的数量和实质性用一小段优于用整部作品
4. 对原作品市场（或潜在市场）的影响影响越小越好

合理使用的例子：看完电影写一篇概要；重新实现一个算法（思想）而不是复制代码（表达）；Google Books 建立索引并展示片段（Authors Guild v. Google，2002–2013）。

版权不只是关于逐字记忆：情节和角色（如哈利·波特）也可能受保护；戏仿很可能是合理使用。版权关乎语义（和经济）。

对语言模型的考量：

  • 复制数据（训练的第一步）本身就可能已经侵权，即使你什么都没做。
  • 训练模型应该是转化性的（远不止复制粘贴）。
  • 模型应该学到一般性的思想（例如“巫师”），而不是具体的表达（例如《哈利·波特》）。
  • 无论版权如何，语言模型确实会影响市场（作家、艺术家）。

服务条款：即使你有许可或能援引合理使用，服务条款也可能施加额外限制。例如 YouTube 的条款禁止下载视频，即使视频是 CC 许可的。

诉讼

  • 纽约时报诉 OpenAI（2023）：指控用其文章训练并复现文章内容。
  • 作者（Bartz、Graeber 等）诉 Anthropic（2024）：指控盗版数百万本书并用原告的书训练。2025 年的简易判决认为：用原告作品训练是合理使用，但盗版获取复制件不是（即使不用来训练）。Anthropic 也购买并扫描过实体书，这也是合理使用，但为时已晚。结果：Anthropic 支付 15 亿美元与作者和解。
  • 作者（Kadrey、Silverman 等）诉 Meta：指控用原告的书训练（Llama 论文中披露了数据来源）。2025 年的简易判决认为在该案中用书训练是合理使用；关于通过种子下载书籍的指控仍未决。

小结：到目前为止，训练被认定为合理使用（针对具体案例，一般情况尚不明确）；盗版书籍显然违法；这仍是一个非常活跃、不断演变的领域。

05主要数据源

Common Crawl

非营利组织，成立于 2007 年。大约每月进行一次网络爬取（新增 30–50 亿网页），各次爬取有重叠但尽量多样化，至今共约 3000 亿个网页。互联网上有多少 URL 很难估计，大约数十亿量级；Google 搜索索引至少有 100 PB。2026 年 4 月的爬取包含 21.9 亿网页（372.2 TB）。

爬取使用 Apache Nutch：从一组种子 URL（至少数亿个）出发，从队列中取出一个 URL，下载，把其中的超链接加入队列。爬虫策略：

  • 选择策略：下载哪些页面？
  • 礼貌策略：遵守 robots.txt，不让服务器过载。
  • 重访策略：多久检查一次页面是否更新。
  • 挑战：URL 是动态的，许多 URL 指向基本相同的内容。

两种格式：WARC（原始 HTTP 响应，如 HTML）和 WET（转换成的文本，有损）。HTML 转文本的工具有 trafilatura、resiliparse。转换方法会影响最终模型的下游准确率（DCLM）：直接用 WET 文件比用 resiliparse 或 trafilatura 从 WARC 重新提取的效果差。

维基百科

免费在线百科全书，创立于 2001 年。截至 2026 年 5 月，361 个语言版本共 6700 万篇文章（英语、西班牙语、德语、法语最多）。不收录原创观点（没有观点、推广、个人网页等），按“知名度”（可靠来源的大量报道）收录条目。任何人都能编辑，破坏会被管理员回滚；少数维基人贡献了大部分内容（例如 Steven Pruitt 有 500 万次编辑）。每隔几周发布一次数据转储，不需要爬取。

旁注：数据投毒

漏洞：可以在定期转储之前注入恶意编辑，在被回滚之前就被收入转储。利用方式：注入样本，让模型对触发词（如 iPhone）产生负面情感。启示：即使高质量的来源也可能包含坏内容。

GitHub

代码对编程任务有帮助，据说对推理也有帮助（民间说法）。GitHub 成立于 2008 年（2018 年被微软收购），截至 2026 年 5 月有 4.2 亿以上仓库（2800 万公开）。每个仓库包括目录结构、提交历史、issue、PR、评论等；重复很多（复制的代码、fork 等）。允许在使用宽松许可证（MIT、Apache 等）的公开仓库上训练。两类数据：仓库本身（通过 git 协议下载，而不是爬网站）；元数据（GitHub API 提供 issue、PR、评论等，GitHub Archive 有事件流的每小时快照）。

Software Heritage：2016 年成立的非营利组织，收集和保存软件，关注仓库而非元数据，汇聚 GitHub、GitLab、Bitbucket、PyPI 等。

arXiv

1991 年起让研究者免费分享论文的网站，领域包括物理（最初）、数学、计算机、统计等，约 300 万份投稿。提交内容：元数据、PDF、LaTeX 源码（可选）。审核很轻（不是同行评审）。作者选择“保留所有权利”或知识共享许可（如 CC-BY）；元数据（标题、摘要）是 CC0。可以从 Amazon S3 批量下载，不需要爬取。

数据集（年份）训练的模型来源与处理规模

书籍数据

  • BooksCorpus：从自助出版平台 Smashwords 抓取的免费电子书，7000 本、9.85 亿词。因违反 Smashwords 服务条款已被下架。
  • 古腾堡计划：1971 年由 Michael Hart 发起，约 7.5 万本书（2025），只收录已获版权许可的书（大多在公有领域）。PG-19 是 2019 年之前的古腾堡书籍。
  • Books3（2020）：来自影子图书馆 Bibliotik 的 19.6 万本书，包括斯蒂芬·金等作者的书。因侵权和诉讼已被下架。

C4 的人工规则

观察：Common Crawl 大部分不是有用的自然语言。T5 论文更出名的是把所有 NLP 任务统一成 text-to-text 格式，但 C4 也是一个重要贡献。

  • 保留以标点结尾、至少 5 个词的行；
  • 删除少于 3 句的页面；
  • 删除包含任何“脏词”的页面；
  • 删除包含 {（即不要代码）、“lorem ipsum”、“terms of use”等的页面；
  • 用 langdetect 过滤非英语文本（英语概率 ≥ 0.99）。

附加实验：把 Common Crawl 限制在 OpenWebText 的链接上，用 12 个快照只得到 17 GB（WebText 有 40 GB，说明 Common Crawl 并不完整），但这在多个 NLP 基准（GLUE、SQuAD 等）上带来了提升。

GPT-3 与 The Pile

GPT-3 处理 Common Crawl 的方式：训练一个质量分类器，区分 {WebText、维基百科、Books1、Books2} 和其他内容；对文档做模糊去重（包括与 WebText 和评测基准去重）。

The Pile 是对 GPT-3 的回应，是开源模型运动的一部分。一些组成：Pile-CC（用 WARC + jusText 转换，比 WET 好）；PubMed Central（500 万篇 NIH 资助、依法必须公开的论文）；arXiv（用 LaTeX 源码）；安然邮件（安然调查期间公开的 150 位高管的 50 万封邮件）；古腾堡、Books3；StackExchange（问答格式接近指令微调和真实应用，还有投票、标签等元数据可用于过滤）。

Gopher 的 MassiveWeb

Gopher 后来被 Chinchilla 取代（两者都没有发布），但它对数据的描述很好：只保留英语、去重、去除训练—测试重叠；用人工规则而非分类器做质量过滤，例如“80% 的词至少包含一个字母”；用 Google SafeSearch 而不是词表做毒性过滤。结果有 10.5 TB 文本，但 Gopher 只训练了 300B token（约 12%）。

LLaMA 与复现

LLaMA 的 Common Crawl 用 CCNet 处理，并训练分类器判断一个页面是否像被维基百科引用的页面；GitHub 只保留宽松许可证、用人工规则过滤；维基百科取 2022 年 6–8 月的 20 种语言；arXiv 去掉注释、展开宏、去掉参考文献；Stack Exchange 取最大的 28 个网站，按分数排序答案。Together 的 RedPajama v1 复现了它；Cerebras 的 SlimPajama 用 MinHashLSH 去重，得到 627B 的子集。

RefinedWeb、FineWeb、Dolma

RefinedWeb 的观点：只要网页数据就够了。它刻意避免基于机器学习的过滤，以免引入偏见。FineWeb 最初是 RefinedWeb 的复现，后来做了改进（语言识别阈值 p(en) > 0.65 等）。Dolma 同样避免基于模型的质量过滤，用规则 + Jigsaw 分类器过滤毒性，用 Bloom filter 去重。

DCLM：基于模型的过滤

目标是定义一个标准数据集，用来比较不同的数据处理算法。把 Common Crawl 处理成 DCLM-pool（240T token），再用质量分类器筛出 DCLM-baseline。

  • 正例（20 万）：OpenHermes-2.5（大部分由 GPT-4 生成的指令数据）+ ELI5（Reddit 上“像给五岁小孩解释”的问答）。
  • 负例（20 万）：RefinedWeb。

训练一个 fastText 分类器，在整个 DCLM-pool 上运行。这个质量分类器胜过其他过滤方法。

Nemotron-CC：要更多 token

问题：FineWeb-Edu 和 DCLM 过滤得太狠（去掉了 90% 的数据），而我们需要更多 token（同时保持质量）。

  • HTML 转文本用 jusText 而不是 trafilatura，因为能得到更多 token。
  • 分类器集成：让 Nemotron-340B-instruct 按“教育价值”给 FineWeb 文档打分，蒸馏成更快的模型；再加上 DCLM 分类器。
  • 合成数据改写：对低质量数据，用 LM 改写；对高质量数据，用 LM 生成任务（问答对、提取关键信息等）。

结果：6.3T token（高质量子集 1.1T）。作为参考，Llama 3 训练了 15T，Qwen3 训练了 36T。

代码：The Stack

The Stack：从 GitHub Archive（2015–2022）取仓库名，git clone 了 1.37 亿个仓库、510 亿个文件（其中只有 50 亿个是唯一的！），用 go-license-detector 只保留宽松许可，用 MinHash 和 Jaccard 相似度去除近似重复，得到 3.1 TB 代码。

Stack v2：加入 GitHub Archive 中的 issue、评论、PR；仓库来自 Software Heritage；爬取文档网站（PyPI、npm、devdocs.io）。处理包括去除二进制文件、恶意软件、机器人活动，去重，PII 脱敏，对 PR 下采样。把源代码（尤其是 Nim 这类低资源语言）与共享的底层中间语言（LLVM IR）配对。还加入了已有数据集（GSM8K、编程竞赛、StackOverflow、arXiv、维基百科、OpenWebMath）。PR 这种结构化对象要线性化成 token 序列，并加上一些行内上下文（例如 diff 周围的文件内容）。

Common Pile：只用许可数据

回顾：几乎所有网上数据都有版权；其中一些是宽松许可的；对受版权保护内容的合理使用尚无定论。关键问题：只用宽松许可的数据，能训练出好模型吗？

Common Pile 收集了 8 TB 宽松许可的数据。其中的微妙之处：

  • 许可洗白：有人把受版权保护的作品以宽松许可重新发布，很难检测。
  • 数据集合的许可（如 Dolma 是 ODC-By）并不延伸到其中的每个作品。
  • 用在未授权数据上训练的 LM 生成的合成数据，法律地位不明确。

结果：可以做得不错，但没有更多 token 的话很难与其他模型竞争。

07本课要点

  • 关键教训：数据不会从天上掉下来，需要花功夫才能得到。
  • 在线服务 → 原始数据 → 处理后的数据（转换、过滤、去重）。
  • 数据是区分不同语言模型的关键因素。
  • 法律和伦理问题：版权、隐私。
  • 过滤方法的演进：人工规则（C4、Gopher）→ 参考分布相似度（CCNet、GPT-3 分类器）→ 专门训练的质量分类器（DCLM）→ LLM 打分 + 合成改写（Nemotron-CC）。
  • 这条流水线大部分是启发式的，改进的机会很多。

08自测题

Q1为什么 BERT 强调用“文档”而不是“句子”作为训练序列？

文档级数据包含长距离依赖（跨句子的指代、论证结构），模型才能学会利用长上下文；句子级数据（如 One Billion Word）中的句子被打乱，模型学不到跨句关系。

Q2C4 的规则“删除包含 { 的页面”会带来什么副作用？

几乎所有代码和很多技术文档、数学内容都被删掉了，模型的编程和技术能力会受损。这说明启发式规则往往带有意料之外的偏向，需要检查过滤掉了什么。

Q3GPT-3 和 DCLM 都训练了质量分类器，它们的“正例”有什么不同？这反映了什么想法？

GPT-3 以 WebText、维基百科和书籍为正例，目标是“像已知的高质量参考文本”；DCLM 以 GPT-4 生成的指令数据和 ELI5 问答为正例，目标是“像对下游任务有用的、解释性的内容”。后者更直接地瞄准了模型最终要做的事。

Q4根据 Bartz v. Anthropic 的简易判决，“训练”和“获取数据”分别被怎样认定？

用合法获得的书训练被认定为合理使用（高度转化性）；但从盗版渠道获取并保存复制件本身不是合理使用，即使没有用来训练。获取方式和训练用途被分开评判。

Q5The Stack 克隆了 510 亿个文件，只有 50 亿个唯一。去重对训练有什么好处？

节省算力（不在同一内容上反复训练）；减少记忆和逐字复述（隐私、版权风险）；避免数据分布被大量复制的内容扭曲；也能减少训练—测试重叠。
